# 手机连电脑的延迟测量

> 最后更新：2026-11-16
> 对应 issue：#IKVGS9

## 为什么需要这个

产品说「优先 P2P，延迟更低」。这句话要么有数字，要么就是广告。

更要紧的是：这类差异无法用嘴解释，也无法用一次「能连上」的验收代替。必须有三组可比的数字：

| 场景 | 网络条件 | 期望 |
| --- | --- | --- |
| A 同局域网直连 | 手机与电脑在同一 Wi-Fi | 最快，建连应在几十毫秒级 |
| B 跨网络直连 | 手机走蜂窝，电脑在另一个网络，打洞成功 | 比 A 慢，但仍不走中继 |
| C 只能走中继 | 任一端在对称 NAT / 严格防火墙后 | 最慢，且受中继地理位置影响 |

## 手机端已经能看到当前路径

任务详情顶部与「设备」页的状态栏会显示 `直连 · 12 ms` 或 `中继 · 68 ms`——这就是链路上实际选中的那条路径与 RTT，来源是 `RemoteClient.pathLabel()`。**这一行本身就是最直接的证据**：走到中继时会明确写「中继」，不会伪装成直连。

## 用测量模式拿可比较的数字

连接组件（`pilot-mobile/bridge`）带一个 `--measure` 模式。它在电脑侧跑，对着**电脑自己的配对票据**连续建连 N 次，输出可直接贴进记录的分位数。

```bash
# 先让电脑生成配对票据（工作台 → 连接手机），再从票据里取 --measure 的入参
cd pilot-mobile
./gradlew :bridge:installDist          # 或直接跑源码：./gradlew :bridge:run --args="..."
build/install/bridge/bin/bridge --measure <票据> --samples 20 --label "A 同局域网"
```

输出是 JSON：

```json
{
  "label": "A 同局域网",
  "path": "direct",
  "samples": 20,
  "connectMs": { "p50": 38, "p95": 61 },
  "firstByteMs": { "p50": 21, "p95": 44 },
  "rttMs": { "p50": 9, "p95": 14, "observed": 20 },
  "details": [ ... ]
}
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `connectMs` | 从发起到建连完成的耗时。每次样本都重新建连，因为用户真正的等待在第一次连接 |
| `firstByteMs` | 建连完成到收到首字节的耗时 |
| `rttMs` | 链路自己报的 RTT；没有观测时为 `null` 并计入 `observed`，**不填 0** |
| `path` | `direct` / `relay` / `mixed` / `unknown`。`mixed` 表示一轮里两类路径都出现过，这种数字不能当同一条件用 |

### 分位数口径

最近秩法：P95 取第 `ceil(0.95n)` 小的值，不插值。样本少时宁可取到最大值，也不用插值把尾部抹平——延迟问题几乎总在尾部。没有样本时给 `null`，不给 0。

## 怎么跑出三组数字

1. **A 同局域网**：手机连家里/办公室 Wi-Fi，电脑在同一网络。`--measure <票据> --samples 20 --label "A 同局域网"`
2. **B 跨网络**：手机切到蜂窝数据，电脑保持原有网络。同样命令，`--label "B 跨网"`
3. **C 只能走中继**：给电脑启动连接组件时显式配置你自己的中继（或让两端处于禁止直连的网络），再用 `--relay <中继地址>` 测量，`--label "C 中继"`

每组至少 20 个样本。跑完把三份 JSON 贴进 `evaluation/MOBILE_LATENCY_<日期>.md`。

## 手机端要同时记的

- 机型与系统版本；
- 网络类型（Wi-Fi 频段 / 蜂窝制式 / 运营商）；
- 两端的地理位置关系（同城 / 跨省 / 跨国）；
- 测量期间是否有其他大流量。

**这些条件不写清楚，数字之间就没有可比性。**

## 一条不要做的事

不要用回环（同一台机器上的两个端点）冒充「直连」。那测的是进程间通信，既不是打洞也不是中继，写进报告只会误导人。

## 当前状态

测量代码与分位数口径已实现并有单元测试（`LatencyMeasureTest` 5 项）。**三组真实数字需要真机与真实网络，尚未采集**——这一项在拿到数字之前不算完成。
