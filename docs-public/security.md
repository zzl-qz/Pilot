# 安全与隐私

> 最后更新：2026-11-09

Pilot 会读取工作区内容、向模型端点发送请求，并可能在本机执行文件修改和命令。它适合由用户监督的本机开发与评估；不要把它当作可信代码执行沙箱、备份系统或公网多用户服务。

## 使用前的建议

1. 先在可丢弃的测试仓库和独立数据目录里试用。
2. 第一次执行任务前，把默认权限从 `AUTO` 切换为 `ASK` 或 `READ_ONLY`。
3. 查看每次审批的目标、路径和命令；不确定时拒绝。
4. 将 API 密钥保存在当前 shell 环境或本机忽略文件中，不要放进工作区。
5. 在发送任务前，确认工作区与提交给模型的内容不含不应外传的数据。

## 工具权限和本机执行

| 模式 | 行为 |
| --- | --- |
| `AUTO` | 普通工具可以直接运行；某些工具自身要求确认的操作仍会触发审批。 |
| `AUTO_EDIT` | 文件写入可直接运行；命令仍需审批。 |
| `ASK` | 只读工具可直接运行；文件写入和命令需要逐项批准。 |
| `READ_ONLY` | 只读工具可运行；写入和命令被拒绝。 |

权限模式只决定 Pilot 是否要求审批，不是操作系统隔离。文件工具有工作区路径校验，但**主会话中的 `run_command` 由宿主进程执行**，其可访问范围取决于操作系统账户及项目配置。容器隔离目前用于特定子任务命令与提案校验，不会自动包住所有主会话命令，也不会因容器不可用而静默替代为完整安全沙箱。

文件修改与命令执行都有本机副作用。检查点只覆盖 Pilot 能记录快照的部分文件写入；命令、其他进程或未被快照工具跟踪的更改可能无法由消息检查点恢复。请用 Git 和独立备份保护重要数据。

## 模型服务与工作区数据

真实模型请求会发送完成任务所需的提示词、用户输入、相关工作区内容以及工具结果到你配置的模型端点。端点可能由第三方运营；其保留、训练和处理策略由对应服务商决定。Pilot 不会因为工作区在本机，就让模型调用自动保持本地。

发送前应检查任务涉及的文件，不要让密钥、个人信息、客户资料或专有数据进入提示词和工具结果。需要离线或严格本地处理时，不要配置外部模型端点，并确认应用实际使用的模型运行方式。

## 本机存储和保留

默认数据目录是仓库根目录下的 `.pilot/`，可能包含 SQLite 会话数据库、附件、文件快照、成果、命令日志、访问审计记录和 trace。可以通过 `PILOT_DATA_DIR` 指向独立目录。

事件、快照和 trace 默认不自动清理。配置正数的 `PILOT_RETENTION_DAYS` 后，服务按保留期限清理相应旧记录；这不等同于安全擦除，也不会删除会话本身。`.pilot/` 被 Git 忽略并不意味着可以公开上传或任意共享。

## 远程访问

默认 `PILOT_SECURITY_MODE=local`，只允许本机回环访问。启用 `token` 模式会允许持有共享访问令牌的客户端访问；当前没有用户、角色或会话级隔离。令牌不是面向公网的身份系统。

不要直接把 Pilot 端口开放到互联网。确需远程访问时，应先配置 TLS、受维护的认证代理、防火墙和精确的允许来源，并限制到可信网络与必要用户。不要把带令牌的 URL、浏览器历史或代理日志公开；SSE 客户端对认证请求头有限制，因此令牌可能以查询参数形式传递。

手机连接是可选功能，不代表服务默认开放公网。公共发现或中继的可用性受网络条件影响，也不替代访问控制。连接边界见 [Android 与移动连接](../pilot-mobile/README.md)。

## 报告安全问题

漏洞报告方式见 [SECURITY.md](../SECURITY.md)。目前仓库没有公布专用安全邮箱或单独的响应承诺。请不要在公开 Issue、截图或日志中粘贴访问令牌、API 密钥、个人数据或可直接利用的漏洞细节。若 GitHub 仓库启用了 Private vulnerability reporting，请优先使用该私密入口；若没有，请先通过维护者公开资料联系维护者，请求一个私密报告渠道，再发送复现细节。
