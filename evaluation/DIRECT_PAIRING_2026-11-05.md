# 默认直连与本地出码验收（2026-11-05）

按用户明确要求：后端未配置中继时不启用公共中继及公共发现服务，不等待中继上线，只尝试可达地址的 P2P 直连。只有 pilot.mobile.relay 明确配置了地址与端口，才使用对应中继。PC 启动仍不构建移动源码，也不准备 Gradle / Android SDK / Java 21。

## 原因

旧版 createEndpoint 在没有中继配置时使用 iroh 默认公共服务，Main.kt 又在签发配对码前等待 endpoint.online，20 秒未完成就使整个出码失败。因此“没有手动配置”并不代表旧实现没有使用中继；截图中的超时发生在电脑连接公共服务，尚未连接手机。

本轮旧版本诊断中，默认四个公共域名的 DNS / TLS 均可达（根路径返回 404），但真实 iroh 公网探针在 30 秒内未完成。HTTPS 探测不能当作 iroh 握手成功。用户明确默认策略后，没有继续依赖公共服务进行验收。

上游说明 online 等待中继握手、无 WAN 时可能一直等待：[Endpoint 文档](https://docs.rs/iroh/latest/iroh/endpoint/struct.Endpoint.html#method.online)。最终修复按用户策略禁用默认中继，不用“先显示二维码”掩盖实际连接条件。

## 修改

- 默认使用 Minimal preset 和 disabled relay mode；不再包含默认公共服务分支。只有显式 relay 列表使用 customFromUrls。
- 默认签发的票据不含中继，developmentRelays 为 false；只在配置了中继的分支等待对应中继。旧保存数据中的开发标记不再启用公共服务，未配置时剥离旧票据的中继路由，保留电脑公钥与直连地址。
- 后端 application.yaml 明确留空默认值。错误和界面区分“本机生成配对码”“准备已配置的中继”，不再统一称为正在连接手机。二维码未生成时隐藏复制入口，避免展示无效操作。
- Web、桌面、独立配对页和 Android 设备说明同步展示真实配置模式。显式中继故障不回退到公共中继。
- Android 更新为 0.2.4-preview，既有保存数据兼容。中继探针现在也要求显式地址，未配置时停止。
