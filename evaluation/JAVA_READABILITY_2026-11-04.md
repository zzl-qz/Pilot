## 人工调整的主要流程

- `AgentLoop`：拆出完成检查、候选重验、并行只读执行。保留用户引导、权限检查、取消、消息协议顺序和检查点时机。并行结果仍按请求顺序汇集。
- `AgentRunService`：拆出运行事件处理、完成回执、子代理用量归集；用有名字的状态集合和分支替换嵌套三元表达式。
- `ScheduleService`：分离前置检查、已派发任务恢复、到期判断和运行领取/投递；保留 CAS、身份复核和失败释放顺序。唤醒次数、恢复次数、等待间隔和总时限改成有含义的常量。
- `MultiAgentController`：接受改动的入口只负责工作区锁与异常映射；恢复、候选版本校验、仲裁检查、硬校验和应用仍在同一锁内按原顺序执行。
- `CommandVerificationGate`：分离 Maven / Gradle / npm 计划、工具链探测、执行和失败诊断；保留构建先后顺序、网络策略、缓存隔离与源码未改写校验。
- `RequestTotals`：内部累计字段明确命名为输入、输出、缓存读写 Token；外部访问器和 JSON 结构不变。
- `RunSubmissionService`：原始投递异常继续抛出，失败回执再次出错时以 suppressed exception 保留原因；同一异常对象不会触发自抑制错误。

## 仍需独立评估的事项

检查通过不表示手册的所有语义要求全部满足。仍有 36 个生产方法超过 60 行，包含工具定义、解析器和状态机；其中 `MultiAgentService.dispatch`、`GoalExecutionPolicy.observed`、模型响应解析等适合后续逐个拆分并配套协议测试。`AgentLoop` 和 `AgentRunService` 的入口仍较长，本次先拆离边界明确的职责。

并发扫描还定位到运行队列、工作线程和通知投递使用 `Executors` 工厂。固定池的队列容量、cached pool 的线程上限，以及超载时的拒绝/持久化/取消行为，需要一起设计；本轮保留现有吞吐与排队语义，没有机械换成一个任意容量。虚拟线程的任务数约束也需要结合各调用方预算和许可审阅。

对可预期的能力探测、清理和关停异常，本轮保留原有降级行为；不能将所有 `catch` 一律改成抛出，或向用户回显可能包含敏感参数的完整异常。后续异常治理应逐条确认可观察性和脱敏边界。
