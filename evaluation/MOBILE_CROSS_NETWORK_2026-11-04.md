# 安卓真机跨网连接排查 · 2026-11-04

后续 0.2.2-preview 已叠加工作台传输与交互延迟优化，见 [延迟优化与验收](MOBILE_LATENCY_2026-11-04.md)。下述 0.2.1 记录保留阶段性证据，不代表 0.2.2 已经完成真机回归；用户已安排下次接入手机时验证。

## 现场与已证实结果

- 真机 vivo V2352A，Android 15 / API 35 / ARM64。用户确认手机与电脑处于两个独立网络；Android 默认网络检查为 CELLULAR，验证通过。USB 仅用于安装与读取 Pilot 日志，没有配置 ADB reverse / forward 传递业务数据。
- 初始表现为扫码后连接超时。电脑连接桥仍在运行；隔离 macOS / Linux 容器公网中继探针成功，RTT 1103 ms。该探针只说明电脑侧测试链路，不替代手机侧验证。
- 真机能够解析中继域名。HTTPS 探测出现抖动：IPv4 请求成功，部分 IPv6 TLS 探测超时；带点和不带点的域名均在 IPv4 探测成功，不能把域名末尾的点当作根因。
- 后续电脑端已记录该 vivo 授权。第一轮 0.2.1-preview 修复包实际运行日志显示：18:38:19 完成中继握手，RTT 1122 ms；18:38:21 收到 HTTP 200，RTT 1080 ms；18:38:26 读取完 183353 字节工作台快照，整次请求耗时 8291 ms。该结果证明至少一次真实跨网业务读取成功，不能推导所有网络成功率或长时稳定性。
- 真机最初仍运行旧包，随后安装日志与 package 版本核对确认已更新为 versionCode 3 / 0.2.1-preview。保留配对数据，未清除常规 App，也没有执行模型任务。

## 代码修正

1. 配对成功后直接复用已建立的 Endpoint / QUIC 连接，交给工作台，不立刻拆掉再冷启动。
2. 请求 / 读取超时、原生连接异常会使缓存连接失效，下次重新握手；按连接对象归属清理，防止并发请求的旧错误关闭新连接。不自动重放修改请求，保留既有待核对回执机制。
3. 连接的原生关闭与资源释放放到不可取消的 IO 上下文，避免同步 FFI 清理阻塞 Android 主线程和其他在途回调。页面销毁同样在 IO 上下文清理。
4. 只读超时显示读取 / 重连提示，写入超时继续要求核对指令结果。增加阶段、HTTP 状态、字节数、耗时与路由类型的诊断日志，不记录票据、配对码、正文或密钥。
5. 升级 APK 版本号，便于判断真机实际运行的包。
