# 0.2.5 跨网恢复与 TUN 兼容验收

日期：2026-11-05。基于 `4a0534d`，使用隔离工作树、临时数据与 Pilot 专用模拟器。模型 API 调用为 0。没有修改系统 DNS、代理、hosts、路由、证书或其他项目的设备。

## 现象与判断

- 11 月 4 日 vivo 日志实际记录了“中继 · 1122 ms”和成功读取；不能把昨天成功当作纯 P2P 成功。
- 0.2.4 按此前要求关闭未配置的公共服务，票据仅含局域网 / 虚拟网卡候选，两端不同私网不保证可达。用户本轮明确同意恢复自动公共服务。
- 当前电脑开启 TUN。系统 DNS 返回 Fake-IP，HTTPS 探测可达；FFI 1.2.0 原生日志持续报告 DNS 错误，无法完成中继握手。仅将官方 FFI 替换为 1.1.0，保持相同网络与 TUN 设置，握手及实际中继往返成功。
- 因此电脑桥与 Android 从同一 `pilot.irohVersion=1.1.0` 属性锁定依赖。这个结论针对已复现的环境，不声称所有代理软件均兼容。后续升级需重新覆盖 TUN 与公网往返。

上游依据：[FFI 1.2.0 依赖声明](https://github.com/n0-computer/iroh-ffi/blob/v1.2.0/Cargo.toml)、[iroh 原生 DNS 迁移记录](https://github.com/n0-computer/iroh/releases/tag/v1.2.0)。具体环境是否受影响以实际连接验证为准。

## 实现

- 默认 `pilot.mobile.mode=auto`：公共发现、尽力直连、必要时中继。显式 `direct` 禁用公共服务；指定 `relay` 时只使用指定服务，与 `direct` 互斥。
- 出码只读取本机端点地址，不等待任何外部服务。自动模式与自建中继均在后台探测、超时重试，状态与配对接口独立。
- 状态轮询更新就绪后的路由及 PNG，保留原凭证、原截止时间；不复活已过期或已消费的码。不同网络应等待电脑显示初始化完成后扫码。
- `ready` 表示完成初始化，不充当持续在线监测。实际直连 / 中继与 RTT 由手机显示。
- 手机按二维码保存自动 / 自建 / 直连策略；旧的显式直连记录不静默改为公共模式。0.2.4 用户更新两端后需重新扫码刷新策略。
- Web、Electron、独立管理页分别展示本地出码及网络准备状态。失败时保留二维码，提示 DNS / TUN / 防火墙检查。
- 不将 Gradle、Android SDK、Java 21 检查加入普通 PC 源码启动；移动构建仍单独执行。
