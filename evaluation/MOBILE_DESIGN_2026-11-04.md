# Pilot 移动工作台设计与验收 · 2026-11-04

## 产品目标与实现选择

个人离开电脑后，可以快速知道任务进展，处理待确认操作，再补充下一条要求。桌面继续执行，手机是应用级工作台。

采用现有 Kotlin / Compose 与原生连接层，重建设计系统和页面组合。本轮没有切换成 WebView：现有扫码、系统文件、语音、Keystore、QUIC 与生命周期均已接入，Compose 可以直接替换颜色、字号、形状与组件组合，不需要为了样式增加 JavaScript 桥和新的导航 / 输入恢复链路。用户支持混合技术的偏好已知；以后若需要 iOS 与 Web 共用界面，可以沿用此处页面结构、视觉角色与交互边界再评估。

参考依据：

- [Compose 自定义设计系统](https://developer.android.com/develop/ui/compose/designsystems/custom)：允许扩展或替换 Material 的设计系统，不要求使用默认组件外观。
- [Android 触控与语义默认值](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)：48dp 触控区域和按功能提供的辅助语义。
- [Linear Inbox](https://linear.app/docs/inbox)：需要关注的事项与其他更新分层，行动在上下文中完成；这里只借鉴组织方式。
- [Android 自适应布局](https://developer.android.com/develop/ui/compose/build-adaptive-apps)：按可用窗口布局，支持不同大小和输入形式。本轮实际覆盖手机及受限宽度场景，不宣称完成平板或折叠设备实测。

## 真实数据与任务清单

设计对象为电脑、项目、任务、运行状态、审批、消息、队列、附件、成果与上下文用量。通常是个人少量电脑、多个项目、少数正在运行的任务；不添加虚构统计、增长率或营销内容。状态和数量来自当前数据列表，单台电脑及草稿仍按既有身份隔离。

| 页面 | 首先回答的问题 | 主要操作 |
| --- | --- | --- |
| 连接 | 如何连接自己的电脑？ | 扫码；粘贴配对码作为替代 |
| 任务 | 哪个任务正在运行或需要处理？ | 打开任务、新任务；搜索与筛选 |
| 对话 | 做到哪了，下一步我需要做什么？ | 审批、补充要求；暂停 / 继续 / 停止 |
| 资料 | 这次任务产生了什么？ | 成果、改动、用量；底部面板查看 |
| 项目 | 在哪个工作区继续？ | 打开现有任务、在项目里新建 |
| 收件箱 | 什么事项需要我确认？ | 优先处理审批，再查看结果 |
| 设备 | 当前连接哪台电脑？ | 切换、添加与移除；选择外观 |

## 视觉与交互决定

使用 `design-taste-frontend` 的 app 流程，选择 **True-black flat**，seed **651736644**，保留 Pilot 的既有中性色与平台无衬线字体；颜色角色映射到原生 Compose，触控尺寸按手机提升到 48dp。产品标记是 Pilot 指南针；产品辨识元素为“电脑连接状态 → 当前任务执行状态 → 待确认操作”，而非装饰性的仪表盘。没有重新抽取方向。

- 扁平底色、一个明度层级的面板、统一 12 / 14 / 16 / 22 / 24sp 字号角色，状态才使用少量绿 / 琥珀 / 红；主操作黑白反转。
- 任务列表采用填充搜索框、横向可滚动的下划线筛选、状态点、项目与状态副行、单个更多菜单。
- 顶部保留当前电脑、连接状态和明确刷新入口；底部导航不用默认大色块选中指示，保持四个文字入口。
- 用户消息右侧气泡，助手正文全宽阅读；标题、强调、行内代码和代码块按内容排版，代码可独立横向滚动和复制。
- 暂停 / 继续与当前状态并排，“成果 / 改动 / 用量”收进“资料”，减少平铺按钮。详情面板支持关闭与底部拖动收起。
- 统一的圆角输入区承载文字、附件、语音和发送 / 停止；真实发送仍沿用持久回执与在途草稿保护。
- 列表页面通过 SaveableStateHolder 按电脑和页签保存搜索、筛选与滚动。深浅 / 跟随系统外观偏好独立保存在本机。
- 审批按钮可换行，长标题和目录按容器截断或换行，输入、按钮与导航带明确语义。返回图标使用自动镜像版本。
- 手动选择深浅色时同步独立 Dialog 窗口的系统栏图标，修正旧版 Material 3 弹层仍按系统外观取色的问题。

## 验证与复核方式

本轮使用 **Pilot 专用 emulator-5580（Android 15 ARM64）**。测试使用独立 `com.pilot.mobile.qa`，不清理日常包的数据，没有操作 USB 真机或 emulator-5582，没有调用付费模型。

1. App JVM 测试验证消息内容不丢失：中文、段落、代码原文、未闭合流式代码块、代码中的 Markdown、未匹配的行内标记与 Windows 路径。
2. Android 原生业务测试使用真实 QUIC / SSE 和隔离 HTTP 后端，验证配对码错误、配对、审批任务归属、资料面板、发送在途编辑、队列引导、暂停 / 继续 / 停止、未知结果回执核对、进程重启草稿、返回列表保留搜索、附件上限、多电脑隔离与移除。
3. 组件尺寸测试覆盖 320dp 约束、1.3 / 1.5 倍字体，验证搜索筛选及空结果、配对按钮、审批换行、代码复制、输入区、长电脑名称、项目、深浅主题，并测量主要按钮至少 48dp。完整业务流程使用模拟器原始约 411dp 宽度。
4. 真实业务截图与受限宽度组件截图分开保存；人工检查任务、对话、小屏代码与浅色设备页，按截图修复。原生 Compose 没有网页 DOM，本轮不将 Web inspector 的结果冒充原生检查，使用 Android 截图、语义与触控尺寸测试替代。

测试中发现并修正了旧用例的两处问题：输入框断言应检查 EditableText，不能把占位提示当作草稿；继续后的停止按钮必须等待可用，并确认进入已停止状态。后台额外核对每种控制请求的实际次数，防止 UI 用例结束却没有发出命令。

设计夹具使用“完善手机上的任务管理体验”“核对多设备连接与审批边界”“修复剪贴板附件读取”等示例任务；不进入正式 App，真实界面继续渲染用户自己的数据。

当前结果和截图参见同目录的 [移动验收记录](MOBILE_2026-11-04.md)。截图输出为 `pilot-mobile/build/mobile-qa`，对比材料为 `.pilot-eval/mobile-design/before` 与 `after`。APK 输出为 `pilot-mobile/app/build/outputs/apk/debug/app-debug.apk`。

## 范围边界

本轮是现有 Android 产品的 UI / 交互重设计，未加入后台推送、iOS、生产中继或新的模型调用能力。兼容处理包括系统字体缩放、滚动容器、主题与系统栏、IME / 导航栏 inset、标准文件和语音入口；真机相机、多 OEM、Android 最低版本、平板 / 折叠与横屏仍未完成实测。复杂 Markdown 表格与 HTML 暂按文本保留，不宣称完整 Markdown 渲染。
