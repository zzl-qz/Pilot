# 移动连接延迟优化与验收 · 2026-11-04

## 结论与范围

0.2.2-preview（versionCode 4）已完成代码、后端构建、APK 构建和专用模拟器验收。用户已将真机复测安排到下一次接入，本轮不要求重新连接手机。既有真机中继 RTT 约 1.1 秒，单次 183353 字节读取耗时 8291 ms 的记录来自此前版本；本轮不能据此宣称新包真机耗时已经下降。

优化目标是减少冷连接、重复下载、串行往返和主线程等待。公网链路自身的 RTT、抖动与公共中继限速仍需真机测量；本轮没有改动路由基础设施、硬编码 IPv4、降低加密或自动重放写入。

## 实现

1. 配对成功直接复用已握手的 Endpoint / QUIC 连接。超时后按连接对象归属使缓存失效，下次重新连接；FFI 资源清理放到 IO 上下文，避免阻塞主线程。诊断只记录阶段、状态、路由、字节数与耗时，不记录正文、配对码或密钥。
2. 应用快照中的结果只带列表字段，摘要最多 240 个 Unicode 码点；保留列表所有条目及 truncated 标记。完整检查、文件、研究与验收内容仍由已有结果详情接口读取。
3. 快照由实际返回内容生成 SHA-256 版本，状态未变化时只返回 version / revision / unchanged。已读回执、任务状态和其他列表内容变化会返回新快照。游标仅在当前电脑内存中保存；未知确认会清除游标，下一次重新取全量，不会把空确认当空列表。
4. 首次任务历史从 300 条调整到 60 条，向前分页每次 100 条；历史、活动运行和队列并行读取，周期元数据的三个读取同样并行。不自动拉取全部历史，实时 SSE 按游标续接。
5. JSON 响应协商逐帧 gzip。桥每次读取最多 32 KiB，不先缓冲完整响应；接收端限制压缩帧及解压输出，普通响应总量继续限制 16 MiB。SSE 和二进制文件不压缩，避免影响实时性和文件校验。解压及 JSON 解析不占用 Android 主线程。
6. 首次同步与刷新显示进度；快照读取互斥，刷新按钮在同步中禁用，重复刷新不会取消正在读取的快照。重复前台生命周期通知不会重启监控。

真实加密 QUIC 集成夹具还验证了固定中文 JSON 的 700014 字节解码内容逐字节相同，线上压缩数据帧合计 5427 字节。该内容重复度高，只用于验证压缩协商和多帧正确性，不作为真实业务压缩率。
