# 0.2.6 网络组合、代理与恢复验收

基于 cb655b9，日期 2026-11-05。隔离工作树、临时数据、固定探针；模型 API 调用为 0。没有更改宿主代理、TUN、DNS、路由或防火墙，没有操作连接中的真机及其他项目模拟器。

## 本轮实现

- 电脑通过标准 Java 网络接口枚举可用网卡、IPv4 / IPv6、隧道线索，读取环境 / JVM / 系统代理配置；不依赖 en0、wlan0 等名称，也不固定某张网卡。链路本地地址不误判为没有网卡。
- 系统路由负责选择有线、Wi-Fi 和 TUN。代理线索只用于解释能力，不据此强制更改路径。HTTP/SOCKS 设置、NO_PROXY、系统代理均不被清空或修改。
- 网络采样与连接检查分开在后台执行。首次连接与后续连接状态持续检查；没有网卡时显示 offline，检查失败时显示 unavailable，恢复后自动更新。不会把已选中的中继 URL 单独当作完成握手。
- 状态包含最近检查时间、观察到的配置变化次数及环境概况。HTTP 状态接口不等待代理查询、DNS 或外网握手；二维码本机生成，刷新路由不延长授权或复活已消费凭证。
- Web、Electron 和独立管理页展示网络与代理说明。只返回概况，不返回网卡 IP、代理地址、用户名、密码或内部比较指纹。
- 连接桥到本机后台、后台到本机管理接口显式使用无代理回环请求，避免本机令牌交给代理。模型 API 等其他请求的代理配置不变。
- Android 监听默认网络变化，覆盖 Wi-Fi、蜂窝、有线及 VPN；合并通知后恢复读取，写操作在途时等待结果，不自动重发待核对指令。离线提示不被旧的读取回调清空。
- 切换 / 移除电脑先更新本地状态，在 IO 后台释放旧原生端点，避免关闭等待卡住界面。扫码采用 QR 格式与 TRY_HARDER，和实际 PNG 验证配置一致。

## 兼容矩阵与实际范围

| 场景 | 处理与验证 |
| --- | --- |
| 网线 / Wi-Fi，不开代理和 TUN | 标准系统选路，不要求用户填网卡/IP；Windows、Linux、macOS 风格及任意网卡名的组合模拟通过。未实际插拔实体网线。 |
| 系统 HTTP/SOCKS 代理开启、TUN 关闭 | 检测配置并说明完整代理隧道限制，不修改配置；HTTP/SOCKS、大小写变量、排除规则、无效配置与系统选择器模拟通过。宿主 TUN 未关闭，因此不冒充该组合实机验收。 |
| TUN 开启，代理未配置 | 保持当前宿主 TUN，macOS ↔ Linux 容器实际公网中继往返；真实断开 / 恢复该专用容器网络，旧票据恢复读写通过。 |
| HTTP 代理与宿主 TUN 同时开启 | 容器使用短时认证 CONNECT 测试代理；仅允许 iroh 域名的 443，不解密 TLS；实际 25 次 CONNECT，断网前后旧票据经中继往返通过。 |
| 全局代理也覆盖本机地址 | 真实 Pilot Jar 在 JVM HTTP 代理指向不可达端口且无本机排除规则时，管理、项目、会话、SSE、队列、审批仍通过；原生桥集成测试断言本机转发不调用全局代理选择器。 |
| IPv4 / IPv6 单栈、多网卡、虚拟网卡、无网卡、网卡读取失败 | 概况、状态与失败兜底模拟通过；枚举顺序不制造变化，地址 / 代理端口变化可识别，不泄露地址或认证信息。未做 IPv6 单栈运营商实机。 |
| Android 真正断网 / 恢复 | 仅 emulator-5584 / pilot-mobile-qa；关闭 Wi-Fi / 移动数据后观察离线，恢复原设置后自动读取，保留草稿，不增加提交次数，待核对状态不被清除。 |
| Android 切换 / 移除电脑、进程恢复 | 原生释放移到后台后完整流程通过；未碰 USB 真机或 emulator-5582。 |

代理存在不证明 QUIC 通过代理。当前 FFI 未暴露完整显式 HTTP/SOCKS 代理隧道；只允许该代理出网并禁止原生连接 / 中继直达的网络仍不支持。公共服务、目标网络、防火墙或失效的代理均可能使连接不可用，不能声称任意网络必达。

检测网卡存在也不等于外网可用；隧道线索不等于该虚拟网卡当前承担默认路由。没有为了显示“就绪”而跳过连接校验、禁用 TLS 验证或自动修改网络策略。
