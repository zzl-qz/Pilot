# 模型接入、并发恢复与项目目录选择验收

本轮承接会话 `ses_7c981c5d-ff6a-4166-837c-a7d0e3738c4a` 与 `ses_9fd592fb-104a-44f9-89ad-fded77ba650f`。用户明确授权使用免费本地部署模型，无接口费用预算上限。测试均使用隔离数据与任务工作区；真实用户服务保持运行。

## 修复后的行为

- 模型输出必须有协议确认的有效终态。Chat Completions 的 EOF、仅 `[DONE]`、未知 `finish_reason` 不再补成成功；Anthropic 与 Responses 同样核验终态。截断工具参数不执行，已完成工具不会因模型重试被重做。
- HTTP 总时限覆盖响应头和完整正文；空闲时限覆盖首次输出及连续无数据等待。取消关闭连接，错误正文、成功正文和单条 SSE 行均有上限。模型列表、网页抓取、搜索和其他模型协议统一使用有界读取。
- 根据原会话观测到的正常 694 秒完整请求及 331 秒首段输出等待，将默认总时限与空闲时限调整为 900 / 600 秒。心跳不能延长总时限，用户仍可取消。故障重试预算耗尽后直接保留本地说明，避免再向故障模型追加收尾请求。
- 诊断依据最近一轮运行显示阶段、用量与重试信息，旧暂停记录不再覆盖新完成状态；已完成命令耗时停止增长。
- 原会话收尾又复现了只读总结被完成门催促修改代码的问题。明确的本轮只读或全局禁改文件指令现在阻止实现催办及旧计划催办，仍保留必要的只读核对；若实际已改代码，验证要求不会被跳过。「实现只读接口」和「不要修改测试文件」仍按实现任务处理。
- 修复 POSIX 串联命令重复传入参数，保留 Windows 独立命令构造分支。真实评测又发现工具说明推荐测试接 `tail`、完成检查却不接受管道证据的矛盾；现已统一为独立验证命令与分页日志，严格退出码规则不变。
- 项目编辑支持桌面目录多选、服务端目录浏览、手动绝对路径输入、去重与最多 12 个目录。桌面连接远程服务时明确转为服务端浏览。选择取消不修改结果，失败可重试；IPC 继续校验可信窗口、框架与来源。
- 评测器遇到基础设施异常或宿主长期停调度就停止后续派发，持久保留失败及会话身份。长链路计数使用真实诊断字段；预算覆盖必须存在结构化停止事件，不能从剩余文件推断。场景门槛进入任务指纹。故障控制使用独立凭据，默认保留代理限额；窗口重置不会清除生命周期累计请求和已观测用量。新增显式全过程变更范围，已记录的临时文件创建不能因随后删除而逃过验收；缺少轨迹不放行，规则变更进入任务指纹。该检查不保证发现任意子进程内从未被服务记录的瞬时文件。

远端 `dev` 在开发期间新增 `e5fc497`、`d4f84f1`，已合入并保留故障注入代理和三个场景夹具。重复的流式超时实现统一到 `BoundedHttp`，新增测试按有效业务终态约束修订；没有覆盖或强推远端历史。

## 真实模型记录

模型为 `Qwen3.8-Flash-Next-oQ4e-mtp`。输出记录保留模型配置、源码、提示词、任务与环境指纹；不包含密钥。模型服务未返回可核对的实际路由别名与完整价格，所以 `resolvedModel`、未知费用保持 `null`。

原版本仅运行 3 个任务各一次，3/3 通过，不能据此构成严格 A/B 对照或宣称显著提升。11 月 11 日候选批次计划 72 次，实际建立 54 个会话：22 次及时完成并通过外部验收，28 次取消，另 4 次在宿主睡眠期间未及时观测的完成被保守记为中断；18 次未派发。另一个最终冒烟批次的 3 次尝试也因休眠超时取消。原始失败保留，未用后来完成或重跑结果替换。

11 月 12 日保持唤醒后，对固定 24 个任务各重复 3 次、最多 4 个评测会话并发，使用独立输出与冻结构建。该矩阵覆盖当时的协议、HTTP、诊断及目录实现；主矩阵保留 P0 提示词，后续校验指引 P1 使用独立服务与输出，不混合计算成功率。交付收尾时追加的只读完成门修复另以 macOS / Linux 各 84 项针对性回归验证，未宣称这 72 次是对最后一次改动后的完整重跑。

CSV 超时样本的已保存代码在取消后人工执行 5 项测试通过，仅作为原因分析，未回填原成功率。其轨迹显示反复管道测试触发无法确认退出码的校验提醒；该反馈矛盾已修复。后续模型仍有一次临时文件约束违规，说明模型遵循约束的能力存在波动；本轮修正评测漏检并保留失败证据，没有为得到全绿而放宽要求。

过程范围规则是在观察到违规后补入执行器的，旧模型样本按原提示词与指纹保留。`trajectory-audit.json` 复核了原 CSV 样本、P1 三次与长链路的已记录变更，并核对违规动作在中途引导之后发生；启用新规则后的未来任务会明确告知模型全过程范围并使用新的任务指纹。

## 运行与交付

两个原会话已正常收尾，原计划分别为 7/7 和 4/4，收尾期间没有改动仓库文件，见 `original-session-handoff.json`。两个原会话的工作区已恢复为项目主目录，项目中仅移除了本轮新增的两个临时目录。临时工作树改动先与集成版本核对并留存补丁，再删除临时工作树和对应分支；其他人的工作树保留。

当前用户 IDE 后端仍加载启动时的旧 Java 类，桌面主进程也需重新启动才能加载新的目录 IPC。更新后需要重启 Pilot 后端及桌面；仅刷新网页不能替换旧 JVM 中已加载的类。本轮没有为部署而终止用户正在运行的 IDE 服务。
