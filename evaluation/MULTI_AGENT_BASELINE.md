# 多 Agent 改造前后对照基线（P0-2）

用途：给「多 Agent 是否真的缩短了关键路径」提供可复核的数据，不靠讨论拍板。
每项任务在**冻结的仓库副本**上跑，改造前跑一遍、每个阶段结束后再跑一遍，填同一张表对比。

## 约定

- 记录 `git rev-parse HEAD`，并使用 JDK 25（`pom.xml` 的 `java.version` 为 25；`JAVA_HOME` 指向 17 会出现
  `class file version 69.0` 编译错误）。
- 每项任务跑之前复位工作区（`git status` 干净、`git stash list` 为空），避免上一项的改动污染下一项。
- 判据只能是**可执行的命令结果或文件事实**，不接受“模型说完成了”。
- 分类 AUTO = 现有自动化测试可验证；MODEL = 需要真实模型演练；MANUAL = 需要人工确认。

## 每次运行要记录的字段

| 字段 | 说明 |
| --- | --- |
| 成功率 | 10 项里满足判据的项数 |
| 总 token | 模型返回的用量；未知标为估算，不能当 0 |
| 墙钟 | 从派发到拿到报告的时间 |
| 人工介入次数 | 仲裁、审批、手工修复的次数 |
| 失败类别 | 上下文不足 / 产物没传 / 文件冲突 / 校验失败 / 权限被拒 / 工具缺失 |
| 工作区状态 | 结束时 `git status` 是否干净 |

## 判定规则

| 结果 | 决策 |
| --- | --- |
| 并行任务成功率提升，且 token 增幅 ≤ 2 倍 | 继续投入异步派发、`wait_agents`、`steer_agent` |
| 并行任务无提升或成本翻倍 | 收缩：`dispatch_agents` 降级为只读调研并行 |
| 单 Worker 成功率 < 80% | 停止扩展，预算投向编辑可靠性与验证 |

后两种都是有效结论，不是失败。

### 本次修复与回归证据

1. **侧边对话的异步归属。** A 会话创建未返回就切到 B、不同标签发送失败、重复创建失败、关闭失败后重试，均有浏览器与 Electron 回归。IME Enter 不发送，标签草稿独立保留，选区引用真实点击可用。服务端运行状态恢复后显示停止；发送响应尚未回来时点击停止，会在取得 runId 后取消。
2. **调度与旧结果隔离。** 新重试会使同方案旧租约失效，结果不能继续发布为成功或进入产物集；不同派发与不同并行审阅方案互不取消。启动时收敛遗留派发、节点和尝试，不能等下次派发才处理。真实 SQLite 的双审阅者测试仍能触发分歧仲裁；旧表增加方案字段后保留历史用量。
3. **依赖与完成门禁。** 菱形依赖不会再次叠加共同祖先而覆盖近端的新内容；`src/[AB].java` 与 `src/A.java` 的并行写入被拒绝。有实际改动而跳过验证时，整批不能报告完成。端点未返回 usage 时仍消耗预算。
4. **评估门禁可信度。** 同任务重跑不能冒充 20 个样本；漏掉基线任务必须拒绝；成本按同任务每次运行的均值比较，部分价格未知时不使用便宜子集下结论；基线曾成功不能被最后一次失败掩盖；估算输入不稀释真实缓存命中率。
5. **评估执行器。** 引导改用 `/steer` 并绑定当前 run；取消和暂停被识别为终态；超时不验收并尝试取消自身运行；缺失 fixture 在请求服务前失败；工作区名称不碰撞；发任务前保存原始测试，验收在候选副本中还原测试，删改断言不能假通过；命令超时处理进程树并限制日志大小；dry-run 与严格门禁隔离；输出摘要不覆盖原始记录；无效基线在模型运行前报错。
6. **纠正测试失真。** 旧语音断言仍限定 WebM，现兼容 WAV/WebM/MP4/Ogg 并校验 WAV 文件头；安装命令断言改为跨平台 argv 校验；危险 Git 命令测试检查审批要求，不再把“需要审批”误认为“始终禁止”。浏览器集成测试不连接用户正在使用的桌面壳，并实际执行 4 项测试。
7. **fixture 命令。** 原 `node --test test/` 在本机 Node 22 下报模块不存在，原先“24 个全失败”不能证明验收有效。已改为 `node --test`，24 个未修复 fixture 重新验收均失败；执行器另有“修复实现通过 / 只改测试仍失败”的正反例。尚未完成 24 项真实任务的参考解与真实模型对照运行。

### 仍未闭环的功能

| 优先级 | 问题与实际影响 | 证据与后续验收条件 |
| --- | --- | --- |
| P1 | 可写子任务命令仍在真实工作区执行。文件编辑进沙箱，但命令可能直接改真实文件，也读不到虚拟编辑后的完整代码树 | `WorkspaceToolFactory.registryForScope` / `RunCommandTool.launch`。需为子任务提供独立文件树，使编辑、搜索、命令和验证使用同一候选，并验证真实工作区不被命令修改 |
| P1 | 顺序依赖允许改同一文件，但最终合并仍按多份沙箱检测重叠，没有先把同一依赖链组装成最终版本 | `TaskGraph.overlappingWriters` 允许依赖关系；`MultiAgentService` 把各节点沙箱交给 `MergePrecheck.check`。需覆盖“上游新建→下游继续编辑→接受最终结果”全链路，而不只测下游能读到文件 |
| P2 | `list_dir`、`glob_files`、`search_text` 没有沙箱覆盖视图，新文件或修改后的符号可能搜不到 | `WorkspaceToolFactory.registryForScope` 只有 `read_file` 注入 sandbox。需补新建后列目录、搜索、删除与重命名的统一视图测试 |
| P2 | 预算只能停止后续调度/重试，在途并发请求可能继续消耗；没有严格的 token 或时间硬上限 | `MultiAgentService.Budget` 在尝试结束后累计用量。若需要硬限制，需请求前预算预留、请求超时与取消传播测试 |
| P2 | 派发记录支持查询与启动收敛，不等同于可恢复执行。节点未保存完整文件/工具/命令权限快照，也没有重启后自动续调度闭环 | `JdbcDispatchStore` 的节点字段和调度入口。需保存完整执行约束，再做恢复、幂等和崩溃注入测试；删除会话也尚未清理新增的派发表记录 |
| P2 | 侧边标签依赖本客户端 localStorage；清空缓存或换客户端后，服务端已有子会话没有查询恢复入口 | `side-chat.js` 与 `/side` 创建接口。跨客户端恢复未实现，不能与本次已验证的同客户端标签切换/父子隔离混为一谈 |

这些项有些是原方案尚未实现的能力，有些是新增链路未闭环；不能因为单元测试全绿就标成“已完整落地”。
