# Pilot 对照 Pi 的能力迁移

本文件只比较编码任务处理链：提示词与工具、执行循环、上下文、会话和输入交接。Pilot 保留 Java 服务端、Web 界面、权限与任务记录；参考 Pi 的可观察行为及设计，不依赖 Pi 运行时。对照基于 Pi `main` 分支 2026-10-30 的源码与文档，后续升级须重新核对。

| 环节 | Pi 的做法 | Pilot 当前状态 | 处理 |
| --- | --- | --- | --- |
| 执行循环 | 模型产出工具调用后执行并回填结果；没有新工作时结束，steering 在轮次边界进入 | 已有完整循环和持久检查点，但增加计划、完成门和目标核验 | 保留已有能力；重复调用改按实际结果判停滞，避免误杀状态已变化的任务 |

## 验收方式

1. 批量编辑：一个调用修改两处，缺失或重叠时原文件不变；CRLF/BOM 与沙箱结果一致。
2. 循环止损：相同调用得到新结果时继续；连续相同结果到阈值才提醒和停止；后台任务使用独立观察窗口。
3. 提示词：记录真实请求的 system 与工具定义 token、工具调用数、首次有效编辑前的请求数、最终完成率和返工轮数。短任务与多文件任务各取固定样本，对同一模型和工作区重复运行，只有质量不降且成本改善才继续替换其它段落。
4. 会话/上下文后续改造需验证暂停、重启、压缩、分支和带图队列的恢复，不得丢用户原话、附件或工具证据。
