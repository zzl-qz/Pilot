# Pilot 对照 Pi 的能力迁移

本文件只比较编码任务处理链：提示词与工具、执行循环、上下文、会话和输入交接。Pilot 保留 Java 服务端、Web 界面、权限与任务记录；参考 Pi 的可观察行为及设计，不依赖 Pi 运行时。对照基于 Pi `main` 分支 2026-10-30 的源码与文档，后续升级须重新核对。

| 环节 | Pi 的做法 | Pilot 当前状态 | 处理 |
| --- | --- | --- | --- |
| 执行循环 | 模型产出工具调用后执行并回填结果；没有新工作时结束，steering 在轮次边界进入；同一轮安全工具可并行 | 已有完整循环和持久检查点，但原来所有工具串行、相同参数就可能提前止损 | 已按实际结果判停滞；独立本地读取至多 8 个并行、按调用顺序回填，写入与审批仍顺序执行 |
| 编辑工具 | 同一文件可一次提交多处互不重叠的精确替换，全部基于原文件定位 | 原来每次只能替换一处，连续修改需多个工具调用 | 已迁入批量精确替换；真实写入和沙箱提案共享验证，失败不部分写入 |
| 提示词 | 简短基础说明，工具规则由实际启用的工具贡献，项目规则和技能按需加入 | 已按可用工具过滤部分段落，但通用流程重复且过细 | 已压缩通用流程与静态工具表；还需用真实任务核对质量，不能只凭字数推断改进 |
| 项目上下文 | 沿工作目录的祖先层级加载规则，每个目录取一份，标明来源；技能说明按需提供 | 原来只读工作区根目录首份规则 | 已沿祖先目录加载，保留来源并限制提示词长度；技能按需发现仍待设计 |
| 上下文压缩 | 活跃分支使用摘要，确定性累计读/改文件清单；原始历史仍保存在会话树 | 已有分层压缩与附件保留，但原来只靠模型概括文件线索，对话存储仍是平面快照 | 已在跨次摘要中继承读/改文件清单并附工具目标；仍需把原始事件与压缩视图分离 |
| 会话与队列 | 树形会话分支，steering 和 follow-up 分别交接 | 已有检查点、分支、运行中纠正和队列；附件队列路径正在单独修复 | 先完成消息与图片的同一原子入队，再评估是否需要树形会话存储 |
| 扩展 | 工具、事件、模型与界面可由扩展注册 | Pilot 有固定工具注册和可覆盖提示词，缺少通用扩展 API | 在核心执行稳定且有真实需求时再设计；不因 Pi 有 TUI 扩展就移植无关界面机制 |

## 已有功能的质量差距

- **完成门**：Pilot 原来在普通任务第一次缺少成功验证后只给一次机会，即使随后出现新的源码修改或失败诊断也会停止。现改为只在源码与最近各类验证结果都无变化时停止；旧版成功的受限检查可经现有权限门自动复跑一次，失败信息会继续引导修复，并标出过期检查与本任务改动文件。代码见 [`GoalExecutionPolicy`](../pilot-server/src/main/java/com/pilot/server/agent/GoalExecutionPolicy.java)。
- **上下文保真**：Pilot 的摘要输入原来只写工具名，文件路径靠模型从有限输出中推断。现把工具目标写入摘要输入，读过与改过的文件清单由代码提取并跨次继承；不把模型摘要当作唯一记忆。代码见 [`ContextCompactor`](../pilot-core/src/main/java/com/pilot/core/loop/ContextCompactor.java)。
- **工具吞吐**：Pilot 原来虽允许模型一轮给多个调用，执行仍完全串行。现只并行明确标记安全且无需审批的本地读、列目录与搜索，结果顺序保持稳定；其他工具保持顺序。代码见 [`AgentLoop`](../pilot-core/src/main/java/com/pilot/core/loop/AgentLoop.java)。
- **项目规则**：Pilot 原来只加载工作区根目录第一份规则；现沿祖先目录加载每层最高优先级的规则，按来源分段并限制读取与总提示词长度。代码见 [`ProjectRuleLoader`](../pilot-server/src/main/java/com/pilot/server/agent/ProjectRuleLoader.java)。
- **尚未解决**：Pi 的原始会话树可在压缩后追溯完整历史；Pilot 仍覆盖写入平面模型记忆。Pi 的技能按需加载与扩展机制也比 Pilot 完整。应按真实任务收益与安全边界逐项移植，不能仅凭“已支持”判为对等。

## 验收方式

1. 批量编辑：一个调用修改两处，缺失或重叠时原文件不变；CRLF/BOM 与沙箱结果一致。
2. 循环止损：相同调用得到新结果时继续；连续相同结果到阈值才提醒和停止；后台任务使用独立观察窗口。
3. 验证恢复：同一失败重复交付会停；测试失败后有新诊断或修改源码会继续，直到成功验证或确无新进展。
4. 上下文与并行读取：连续压缩后仍保留早期文件清单；两个独立读取实际并发，回填历史按原工具调用顺序；审批和写工具不并发。
5. 真实模型：记录 system 与工具定义 token、工具调用数、首次有效编辑前的请求数、最终完成率和返工轮数。短任务与多文件任务各取固定样本，对同一模型和工作区重复运行，只有质量不降且成本改善才继续替换其它段落。
6. 会话后续改造需验证暂停、重启、压缩、分支和带图队列的恢复，不得丢用户原话、附件或工具证据。
