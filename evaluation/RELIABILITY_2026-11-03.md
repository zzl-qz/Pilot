# 隔离、恢复与评估验证记录

日期：2026-11-03。基线：`3f4bede`，包括本轮隔离/恢复/评估改动与此前未提交的子智能体 UI 优化。

## 本轮行为

- `dispatch_agents` 的命令改用 `SandboxCommandTool`：只挂载按 scope 过滤的临时目录，覆盖自身和上游提案；真实工作区、`.git`、`.pilot` 不进入挂载。没有可用容器后端时明确拒绝，不退回宿主执行。
- 硬校验也使用此副本，覆盖未跟踪文件和新增提案；命令改写被验证的源文件时判定失败。构建产物只留在临时目录，执行后清理。镜像预装、默认断网、只读容器根、资源限制、原生 argv 引号处理；超时和取消会按本次唯一容器名强制清理，不触碰其他容器。
- 沙箱状态写入失败明确报错；恢复过程串行化，首次写入不会漏掉已有产物，同一 sandboxId 不重复加入。文件原子替换前刷盘，非法路径 ID、损坏 JSON 和无效空状态拒绝继续操作。
- 执行中提案写检查点，运行时不能提前接受；重启后保留提案供审查，旧运行状态改为取消，需重新派发和校验。已有 JDBC 代次租约继续拒绝晚到回执。
- 仲裁先保存后通知；决定持久化，同一回执幂等，不同回执冲突，未知仲裁/无效选项拒绝。决定不会自动写文件或恢复下游。
- 部分接受成功时记录已写文件并使工作区旧验证失效；重试跳过已接受内容，仍拒绝覆盖用户改动。写入完成但状态未保存的相同内容允许安全确认。
- 模型请求与真实子智能体数量分别显示；请求按用途折叠，长列表限高，失败和部分计价保留。结束状态同步到主视图，避免已结束智能体仍显示运行中。提示词移除“读超过五个文件就派生”的机械规则。
- 评估执行器支持相同版本续跑、输出锁和在途标记；保留失败结果，不静默覆盖/重复尝试。新增离线预算规划，不重置历史累计额度，不把未知费用当零。

## 仍未完成的架构目标

恢复目前是“找回产物和决定，明确旧运行中断”，不是完整 TaskSpec、权限快照和输入箱的自动续调度。仲裁选择不自动应用某方案或重启下游。跨文件原子合入/写前日志、全量持久调度事务、机器断电保证、重启后残留容器回收仍未完成。

副本拒绝可见符号链接/特殊文件，以及 32 MiB 单文件、256 MiB 总量、50,000 文件上限之外的项目；历史 commit 校验不支持。命令生成物不自动导入提案，依赖应在镜像中预装。磁盘输出配额和专用依赖缓存尚未实现。主会话的 Seatbelt/bubblewrap 与本轮子任务容器通道是不同边界；Windows 原生限制未实现。本次结果不作为多租户强隔离承诺。
