# 变更应用恢复与隔离构建验证记录

日期：2026-11-04。基线 `c4c7010`，交付前合入远程 `db8bf65` 的平台测试和语音定时器兼容更新。本轮实现 P0 变更应用恢复、P0 构建环境与缓存，以及可复用验证入口；没有追加付费模型调用，未改变评估预算保护。

## 已实现行为

### 接受与恢复

- 接受前获取工作区级 JVM 锁和文件锁，校验、整批预检与应用使用同一锁。`reviewHash` 绑定用户读取的候选内容和状态，校验期间提案变化则返回 409；校验结果不会登记到新候选上。旧客户端缺少指纹时仍在服务端捕获并复核本次候选。
- `<pilot.data.dir>/apply-journal/<workspace-hash>/pending.json` 保存操作 ID、原文、新文、权限、目标工作区版本和阶段。POSIX 上日志目录为 0700、日志文件为 0600，避免备份放宽原文件访问权限；其他平台使用数据目录继承权限。先完整落盘日志，再通过同目录临时文件、刷盘和原子替换应用；文件系统不支持原子替换时明确失败。
- 整批预检发现冲突时不写任何文件。运行时写入失败尝试整批补偿；恢复只允许文件仍与日志的 before/after 相同，遇到用户新修改停止并保留日志。没有对外承诺跨文件同时切换。
- `prepared/applying` 恢复为应用前状态；`applied` 完成沙箱元数据。目标版本号写入日志，避免在版本和沙箱元数据两次落盘之间退出后重复增加版本。重复接受不重复写入。
- 待恢复时阻止清空会话产物。恢复仅由用户后续操作触发，不自动重跑模型、命令或任务。界面提供恢复入口、候选加载失败重试、已处理状态回显，拒绝请求失败不会显示成功。
- 接受请求等待时间与普通 20 秒请求分开，并显示“校验并写入中”；网络超时仍需刷新核对服务端状态，不能把客户端超时当作服务端撤销。

### 构建与缓存

- 容器执行前显式检查本地镜像，项目校验检查工具链。镜像缺失、工具缺失、依赖缺失、构建失败、超时均明确失败；没有宿主回退，也不自动拉取镜像或打开网络。
- 构建命令从叠加提案后的快照推断：Maven `verify`；Gradle `build`；npm 有锁文件则 `npm ci`，按实际存在的脚本执行 build/test。存在依赖却无锁文件时拒绝自动安装；pnpm/yarn 项目要求明确配置 `pilot.multi.verify-commands`，不会改用 npm 重写锁文件。
- `<pilot.data.dir>/build-cache` 按真实项目路径、镜像 ID 和依赖清单分区，挂载到 `/pilot-cache`。不共享宿主 `.m2`、`.npm` 或用户配置。锁文件在挂载内容之外，缓存正在使用时明确反馈重试。子任务命令和接受前校验复用这套机制。
- 网络默认关闭；npm 用 `--offline`、Maven 用 `-o`、Gradle 用 `--offline`。首次需要依赖时，应先明确配置 `pilot.execution.network=true` 预热，再关闭网络重验。该开关允许整个容器校验联网，尚无仅依赖下载的网络代理/出口白名单。
- 构建快照排除 `node_modules`、`.gradle`、存在对应构建文件的 Maven `target`/Gradle `build`，列出排除项；对这些目录的提案拒绝校验。其他目录不猜测是否为生成物。源文件被脚本改写仍使校验失败。

## 验证与复现

实机环境：macOS + OpenJDK 25 + Docker Linux guest + Chrome/Electron。真实构建使用仓库内两个小型项目（带外部依赖、生产代码、构建脚本和断言），不是用 `echo` 代替编译，也不代表任意大型项目已验证。

- Java/Maven：`maven:3.9-eclipse-temurin-25`，JUnit 测试包含正数、负数、整数溢出。
- Node/npm：`node:22-alpine`，固定 `is-number@7.0.0` 和 integrity 锁文件，构建后运行测试，包含零、负数、数字字符串与非法输入。
- 两者都实际验证冷缓存断网失败、联网下载并通过、同一缓存断网通过、故意保留错误逻辑被测试拦下；宿主源文件不变，也不产生宿主 `target/node_modules/dist`。
- 独立 JVM 用 `Runtime.halt(17)` 在日志准备、首文件写入、日志提交前后、版本保存后、沙箱元数据保存后六处退出，再由新实例恢复。这是进程退出实测，不是机器断电实测。
- 其他边界含模拟 I/O 故障、外部编辑、损坏日志、并发/重复接受、候选变化、缓存锁与链接、目录排除、镜像与工具缺失，以及既有容器超时/取消清理。
- Web/桌面恢复流程通过 Playwright 在 Chrome 和 Electron 实际点击；服务端响应由测试路由模拟。覆盖成功、409、412 二次确认携带同一指纹、拒绝失败、恢复、加载失败、已处理状态及 390/1280 宽度。后端逻辑和真实构建由 Java 测试独立验证。

可复现入口（先安装前端/桌面依赖，使用 JDK 25）：

```sh
node scripts/verify-reliability.mjs
# 可选实机部分：需事先准备 alpine:3.20、node:22-alpine、maven:3.9-eclipse-temurin-25
node scripts/verify-reliability.mjs --containers --ui
# 只有浏览器的 runner
node scripts/verify-reliability.mjs --containers --ui --web-only
```

脚本在 Windows 使用 `mvnw.cmd`，POSIX 使用 `sh ./mvnw`；Node 测试文件由 JavaScript 枚举，避免依赖 shell 通配符。GitHub workflow 保留三系统矩阵，新增 Linux 真实构建与浏览器恢复作业和报告上传。仓库 origin 是 Gitee，**提交 workflow 不等于远程 CI 已运行**；Gitee runner 可直接调用同一脚本。

## 兼容范围与仍开放项

Java Path/FileChannel/ProcessBuilder、同目录原子替换、Docker argv 和文件锁用于三平台；POSIX 权限有能力检测，Windows 文件占用或不支持原子替换时报错保留恢复状态。Linux 容器用 POSIX wrapper，Windows wrapper 调用形式仍经过已有映射。没有硬编码用户的 macOS 工作目录。

已做 macOS 宿主、Linux 容器、Chrome/Electron 实测；Windows/Linux 宿主、Podman、Gradle 实际构建尚未实测。小型 Maven/npm 项目验证不覆盖整套 Pilot 在单一镜像中的全栈构建，混合工具链项目仍需准备匹配的镜像/命令。镜像实际 ID 进入缓存键，建议部署配置固定镜像 digest。

尚不包含：完整任务自动续调度、多个沙箱整体接受、机器断电/文件系统损坏保证、对其他编辑器的排他锁、重启后孤儿容器回收、依赖缓存容量与容器输出磁盘配额、自动清理策略、pnpm/yarn 自动适配或多租户强隔离。校验与文件替换均不能阻止不遵循锁的外部进程在最后检查之后写文件。本轮为单用户受控运行环境的可靠性增强。

不自动删除历史缓存或失败现场；清理缓存需在无构建运行时进行，待恢复日志应先通过恢复流程处理。2026-11-03 评估样本不足的结论维持不变。
