# 竖屏扫码与电脑端启动范围验收（2026-11-05）

本轮基于 `6cbe15a` 的独立副本，只叠加本轮改动，未混入工作区并行进行的会话 / 模型修改。使用 `pilot-mobile-qa` 专用 Android 15 ARM64 模拟器；未操作另一项目模拟器和已连接真机。没有付费模型调用。

## 最终范围

按用户最新要求，普通 PC 启动只补电脑所需环境：Java 25、Node/npm、Maven，以及按需准备 Electron。基础运行时位于 `.pilot/bootstrap`；电脑端 Maven、npm、Electron 缓存位于 `.pilot/cache/{maven,npm,electron}`。保留显式配置的缓存位置，不改系统全局 Java / PATH。

PC 启动不检查、不下载 Gradle、Android SDK、移动构建用 Java 21，不自动编译 APK / 连接桥。此前自动构建逻辑、Java 21 下载清单和手机环境报告交接已移除。手机组件仅在打开连接窗口时检查，缺组件提示单独打包；已打包的连接桥使用电脑 Java 25，按需验证电脑原生库。用于本轮冷启动试验的新建项目 Gradle 缓存已停止并清理，原有全局 Gradle、Java 21 和 Android SDK 保留供移动开发使用。

## 二维码通用性

同一 APK / 协议可以扫描任意受支持电脑生成的二维码，运行代码没有绑定某台开发 Mac 的地址或密钥。每台电脑在运行数据目录生成、保存自己的身份，连接票据来自当前端点地址；二维码凭证五分钟、单次有效，只授权生成它的电脑。不同电脑不能互用授权码。新增测试确认两个独立数据目录生成不同身份、拒绝对方凭证、各自配对及重启恢复，撤销一方不影响另一方。现有真实 Android ↔ JVM QUIC 配对回归也通过。

打包脚本只复制后台 Jar、连接桥库、APK 和 Java 运行时，不复制 `.pilot/mobile` 设备身份。分发源码 / 安装包时不要额外复制个人运行数据。
