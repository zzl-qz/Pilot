# 源码启动环境自动补全验收（2026-11-05）

> 后续用户调整范围：PC 启动已移除 Gradle / Java 21 / 自动移动构建，手机组件改为打开窗口后检查。本文件保留原阶段记录，当前实现见 [最新验收](SCANNER_AND_DESKTOP_START_2026-11-05.md)。

本轮面向个人源码运行场景，解决首次运行缺少 Java、Node/npm、连接桥及 Windows 原生运行库时只报 Service Error 的问题。验收副本基于 `5658f04`，只叠加本轮环境改动，避免与工作区同时进行的会话 / 模型修改混合。未调用付费模型，未安装或操作用户手机。

## 实现范围

- Windows `start.cmd` / PowerShell 与 macOS、Linux Bash 先选择可用 JDK 25；缺少时下载固定官方私有 JDK，不改系统 Java、全局 PATH 或 IDE 配置。
- Java 源码准备器检查 Node 22.12+、npm、私有 Maven、连接桥源码版本及 Java 21；构建连接桥不要求 Android SDK。原生探针实际创建无中继端点并生成二维码，不创建配对身份。
- Windows 原生库加载失败时先重试自带 CRT 的私有 Temurin；仍有原生错误才使用 SHA-256 和 Authenticode 均验证的微软 VC++ x64 安装器。正常 UAC、拒绝授权、企业策略均保留，不能静默越权安装。
- IDE / 已构建后台异步准备手机环境，状态请求不等整个下载结束；失败后显式修复，不因轮询不断重装；跨来源不能触发修复。失败不删除授权及任务数据，应用健康接口保持可用。
- 修复 Electron 42+ 不再执行二进制 postinstall 后，项目仍直接准备桌面壳的冷启动错误。现在显式调用官方安装器，验证版本、架构、路径及执行权限，再生成桌面壳。Windows 优先通过 Node 与 npm-cli 参数数组安装，避免批处理展开路径字符。
- 缓存跨进程安装锁、同项目构建锁、独立启动报告、哈希验证、临时文件与原子发布；离线缺包、下载超时、代理、损坏缓存和不支持架构都有明确处理。

## 验证边界

- 没有 Windows 实机；PowerShell 7 在 macOS 的逻辑模拟不等同于 Windows PowerShell 5、DLL 加载或实际 UAC 验证。微软安装器测试均使用替身，没有执行系统安装。
- Windows x64 制品及 DLL 依赖已检查，平台分支和 CI 三平台矩阵已接入；远程 CI 结果尚未取得。Windows ARM64 的 x64 兼容层、Rosetta、Intel Mac、Linux x64 和 Linux 桌面未经本轮实机验证。
- 当前上游连接原生库没有 Intel Mac 制品，手机连接明确降级；不能用自动下载 Java 解决上游缺失的二进制。Linux 自动准备面向 glibc，musl 不在支持范围。
- 本轮不重新证明蜂窝网络 / NAT 穿透成功率。网络可达性、企业代理 / 证书、安全策略及管理员授权仍可能导致环境补全失败；界面会保留重试与 Web 可用路径。
- 不强装 Android SDK、Docker、Xcode；未携带依赖的全新离线电脑不能自动凭空获得运行时。已准备的同系统 / 架构缓存可复用。
