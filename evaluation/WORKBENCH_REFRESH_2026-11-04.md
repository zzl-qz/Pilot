# 工作台刷新与跨设备同步验收 · 2026-11-04

## 问题与修复

原桌面只有 Electron 默认的重新载入菜单，缺少工作台中的可见入口；项目与任务列表主要在启动、本窗口操作后读取，手机或其他窗口修改后可能保持旧数据。

- Web / 桌面右上角增加“刷新工作台数据”，F5 与命令面板提供相同操作。读取项目、任务、当前任务信息、运行状态、消息队列、上下文、计划、任务契约与已打开的变更面板；通知读取失败并保留旧内容。
- 数据刷新不重新激活任务、不重建消息历史或编辑器，不发送、取消或暂停任务；保留草稿、附件与阅读位置。文件树按更新信号刷新已展开目录，保留展开状态；文件引用索引失效后按需重取。
- 每 15 秒在前台同步项目、任务、当前运行状态和队列；后台窗口暂停该轮询。切回窗口、重新可见时完整同步，网络恢复时额外续接 SSE。当前任务进度仍由原 SSE 事件流推送。
- 同一窗口合并并发刷新，手动刷新加入自动刷新时仍执行完整同步与续接。任务切换、离开再返回、新事件先到达时，丢弃过时结果；编辑中的任务契约不被覆盖。等待面板并行请求全部结束后才允许下轮刷新。
- 桌面“视图”菜单明确区分刷新数据与重新载入工作台界面；Cmd+R（macOS）/ Ctrl+R（Windows、Linux）、Shift+F5 重新载入。操作始终指向主工作台，内置浏览器页面保留独立的浏览器重载操作。
- 重新载入前保存当前选中的任务或新任务工作区，并校验文字草稿已完整存储。有未发送附件、文件读取、发送、语音、输入法合成或未保存表单时阻止重新载入，说明原因并提供保留内容的数据刷新替代操作。不会宣称完整页面重载能恢复内存中的附件。
- 未安装新桥接的旧页面和离线提示页仍可通过原生菜单 / F5 恢复；重新载入 IPC 校验主窗口、主 frame 和来源。

## 兼容与实际范围

共享 React / 浏览器 API，不调用系统命令、不硬编码生产文件路径。桌面按平台处理 Cmd / Ctrl，使用 Electron 菜单、IPC 与 webContents；路径恢复测试覆盖 Windows、macOS、Linux 及中文目录。存储不可用明确提示保留当前页面。

实测环境为 macOS 的 Chrome 与真实 Electron。Windows / Linux 为分支及路径模拟，未进行两系统实机 UI 验证。HTTP / SSE 同步专项使用隔离夹具；不能将其视为手机跨公网连接的再次验收。本轮没有操作真实手机、任何模拟器或个人数据库，没有调用付费模型。浏览器工具栏强制刷新、进程被强制结束等不经过应用保护的操作，仍不能保证内存附件恢复。

前端与后端静态包需在运行服务中更新；更新后重新启动后台及桌面一次，后续即可使用新增刷新入口。
