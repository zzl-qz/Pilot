# T001 — `BrowserHome` 遵循显式 `PILOT_DATA_DIR` 配置

- **级别**：L1（单模块已知根因）
- **来源**：实测产品缺陷 `P-001`（Stage 1.1 worktree 复用 `PILOT_DATA_DIR` 启动日志复现）
- **类型**：明确需求（带路径）
- **预期改动范围**：
  - `pilot-server/src/main/java/com/pilot/server/browser/BrowserHome.java`
  - `pilot-server/src/main/java/com/pilot/server/common/data/PilotDataDir.java`（如需暴露是否显式配置）
  - 对应单元测试（如 `BrowserHomeTest.java`）

## 冻结任务原话（原样下发给 Pilot）

```text
我在一个新的 git worktree 里启动 pilot-server，并且显式传了 `PILOT_DATA_DIR=/path/to/shared/.pilot` 想复用已有数据目录，结果发现 `pilot-server/src/main/java/com/pilot/server/browser/BrowserHome.java` 依然把浏览器目录指到了当前 worktree 下的 `.pilot/browser`，导致启动时又重新下载 400MB Chromium，桌面端点文件也没和共享数据目录对齐。

请修一下这个问题：
1. 当显式配置了 `pilot.browser.home` 时，继续按原规则优先使用 `pilot.browser.home`；
2. 否则，如果用户显式配置了 `pilot.data.dir` / `PILOT_DATA_DIR`，`BrowserHome` 应当使用该数据目录下的 `browser`（即 `dataDir.file("browser")`），不要强行回落到当前源码仓库/worktree 下的 `.pilot/browser`；
3. 当既没显式配 `pilot.browser.home` 也没显式配 `pilot.data.dir` 时，保持现有在源码仓库中落到仓库根 `.pilot/browser`、否则落到 `dataDir.file("browser")` 的兼容行为；
4. 补齐覆盖上述全部优先级与跨平台路径处理的单元测试，跑通相关测试与格式/质量检查。

注意：只改本任务相关文件，不要执行 `git commit`、`git push` 或 `git remote`。
```
