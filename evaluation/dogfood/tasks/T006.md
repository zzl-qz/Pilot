## 冻结任务原话（原样下发给 Pilot）

```text
我们现在发给模型的消息序列里，有一些是运行时内部注入的 `user` 角色消息（比如 `<system-reminder>`、`[工具图片]` 以及模型切换提醒），但现在 OpenAI 兼容和 Anthropic 适配器按普通 `user` 消息来切分「最近一轮用户消息」，导致追加 `<system-reminder>` 或 `[工具图片]` 后，之前同轮 `assistant` 消息里的 `reasoning_content` / `thinking` 字段突然被剥离，直接破坏了线上传输层的 Prompt Cache 前缀；另外 Anthropic 适配器会把所有 `system` 角色消息拼进顶层 `system` 字段，尾部临时引导一出现/消失就会让顶层 `system` 变化。

请完成以下改造：
1. 在 `pilot-core/src/main/java/com/pilot/core/message/Message.java` 统一新增 `isInternalUserMessage()` 与 `isRealUserTurn()`；并检查 `MeteredModelClient` 里的模型切换提示前缀，使其能被统一识别为内部提醒而不是新的真实用户轮次；
2. 修改 `OpenAiCompatibleModelClient` 与 `AnthropicMessagesModelClient`，改用「最后一个真实用户轮次（`isRealUserTurn()`）」作为历史 `assistant` 思考字段回传边界：追加 `<system-reminder>` 或 `[工具图片]` 等内部注入消息时，不得剥离当前轮已有 `assistant` 的 `reasoning_content` / `thinking`；直到出现下一条新的真实用户消息后才停止回传旧轮思考；
3. 修改 `AnthropicMessagesModelClient`，仅将 `index == 0` 的主 `system` 放进顶层 `system` 字段，把 `index > 0` 的尾部临时 `system` 引导（如 `phaseHint`、`[Runtime guidance`、`[路径规则]`）序列化到 `messages` 末尾并遵守交替角色规则，确保顶层 `system` 字节稳定；
4. 同步检查 `OpenAiCompatibleModelClient`、`AnthropicMessagesModelClient`、`OpenAiResponsesModelClient` 在容量/上限读取上是否与 `ModelCapacity.active()` 一致，避免只读 `configured()` 导致和 `AgentLoop.admissionLimit()` 偏差；
5. 新增/补充 `pilot-core/src/test/java/com/pilot/core/model/CacheWireTest.java`（用本地 HTTP/序列化回放验证：① 追加 `<system-reminder>` 与 `[工具图片]` 后前面消息的线上传输 JSON 完全一致且保留 `reasoning_content`；② 新真实用户消息到来后停止回传旧轮思考；③ Anthropic 尾部临时 `system` 出现/消失时顶层 `system` 完全一致），并跑通相关单测和格式/质量检查。

注意：只改本任务相关文件，不要执行 `git commit`、`git push` 或 `git remote`。
```
