## 冻结任务原话（原样下发给 Pilot）

```text
目前 `MeteredModelClient` 统计 Prompt Cache 前缀连续性时，是在高层抽象 `Message` 上做哈希，无法感知 OpenAI 兼容或 Anthropic 适配器在线上传输序列化阶段（比如 `reasoning_content` 被剥离、尾部 `system` 改写）引入的真实报文变化；同时 `RequestReport.Prefix` 也缺「首次分叉下标」和「细粒度原因」，排查缓存抖动时看不清到底哪里变了。

请完成前后端配套改造：
1. 在 `pilot-core/src/main/java/com/pilot/core/model/ModelClient.java` 新增默认方法 `wireMessageHashes(List<Message> messages, List<ToolDefinition> tools)`，并在 `OpenAiCompatibleModelClient` 与 `AnthropicMessagesModelClient` 中实现——对实际线上传输序列化后的消息（含思考字段与 system 处理结果）计算确定性哈希列表；
2. 向后兼容扩展 `RequestReport.Prefix`，新增可选字段 `firstDiffIndex`（`Integer`，可为 `null`）与 `detail`（`String`，可为 `null`），保留原有 4 参数构造器，确保旧 SQLite 事件 JSON 缺这两个字段时可安全反序列化为 `null`；
3. 更新 `MeteredModelClient.inspect()`，优先比对线上传输哈希并在前缀未完全复用时给出 `firstDiffIndex` 与清晰 `detail`（区分 `tail_ephemeral_shift`、`head_summary_or_drop`、`mid_history_rewrite`、`wire_payload_changed` 等原因）；
4. 更新前端 `pilot-web/frontend/src/types/runtime.ts` 与 `pilot-web/frontend/src/components/RequestUsage.tsx`，当 `prefix.detail` 存在时展示友好的中文说明，不破坏既有汇总指标与布局；
5. 补齐 Java 单测（`CacheAccountingTest`、`RequestReportCodecTest` 覆盖旧 JSON 兼容解码）及前端单测，跑通对应 Java/前端测试与 `spotless:check`/`checkstyle:check`/`quality-gate.mjs`。

注意：只改本任务相关文件，不要执行 `git commit`、`git push` 或 `git remote`。
```
