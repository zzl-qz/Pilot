# 模型接入与长任务验证：2026-11-13

本轮模型接入可靠性修复及计划内实验已完成并归档：180 次常规任务尝试、9 次真实定时唤醒，另保存预算任务的继续执行段。已知失败全部保留。这里的成绩只适用于固定任务、版本与环境，不代表整个 Agent 的全部能力已达标。

## 已补的问题

- **重复保护误判**：共同开头或高度相似的代码行原来可能被当作复读而中止。现在按完整相同长句、真正的逐行扩写及完整行边界判断；正常正文和推理流均有回归，原有真实重复样本继续通过。未增加模型名称分支，也未改变提示词。
- **预算收尾机会不足**：新增接近步骤/请求上限的通用提醒，在现有额度内保存用户要求的台账或检查点；不自动加额度、不放宽文件范围。这会改变提示词指纹，使用独立新构建复测。
- **自动续跑状态缺失**：补新一轮 `run.started`，避免后台正在继续而界面、诊断仍显示上一轮失败。评测器在终态后同时检查活动运行，并按真实活动 runId 清理，避免交接窗口内提前验收或继续时报 409。
- **故障注入假覆盖**：原代理按 HTTP 数据块截断，首块恰好包含整条回答时可能连终止标记一起发出。现在只先发完整且不含终止标记的 SSE 事件，再制造断流或停顿；合并数据块、UTF-8、CRLF、错误与超限输入均有测试。
- **评测启动与汇总**：修复目录别名启动时静默空跑、内联导入报错；允许显式启用私有 IPv4 HTTP 模型代理；未知 token 用量保持未知，已知小计单列，不能把失败样本记成零消耗。
- **定时任务被强制调研**：新增默认关闭的 `requireResearch` 选项，表单、模板和周期派发保持一致。显式启用时保留调研门禁，旧任务保留已保存策略；未要求调研的本地任务可以直接执行。完成证据核验没有放宽。
- **核验用量回退**：独立核验请求结束后重新读取最新执行状态，避免旧快照覆盖刚增加的请求和输入输出用量。COMPLETE、CONTINUE、WAIT 三种决定都有回归，达到预算后仍拒绝下一次真实调用。
- **历史证据被错误作废**：后续文件变化不会抹掉已成功预约等待的事实；有界保留最近四条成功等待。核验器收到证据范围、是否可引用和具体拒绝原因。历史等待只证明操作发生，当前代码和测试仍必须使用当前文件版本的证据；失败记录、未知引用、重复和非整数条件索引继续拒绝。
- **持续验证**：补三平台 CI 定义与确定性进程重启回归。本仓库远程为 Gitee，新增 GitHub Actions 定义不等于三平台 CI 已执行。

用户列出的提前 EOF、响应体总时限与空闲时限已有生产实现。本轮重新覆盖 Chat Completions、Responses、Anthropic、本地 HTTP 错误正文及分片边界、取消、重试与不完整工具调用；不把已有实现算作本轮新修复。

## 原始真实模型矩阵

冻结生产代码 `8496d32`，24 个任务，每任务每模型独立运行三次，共 144 次。每次使用新工作区，外部验收恢复原始测试；任务期限内取得完成终态、外部验收通过且所需场景实际触发，才计成功。模型为用户授权的自部署服务，无付费云端调用；名称来自端点报告，未独立核验权重。

Linux 列仅在容器中对相同候选代码恢复原测试后验收，没有重新调用模型。第二组有一份超时产物事后通过测试，原始超时仍计失败。两组正常收尾且有外部验收的样本均未出现验收失败；这不是所有任务都完成的证明。

失败原样保留：

1. 主模型 `steer-constraint-hold` 第三次触发 `MODEL_REPEATED`。当时的流式正文没有完整持久化，不能证明这个具体失败由误判造成；另行构造的回归明确复现了共同前缀误判，并据此修复。
2. 第二个模型 `long-file-targeted-edit` 第一次超过固定 12 分钟期限。取消后确认已结束；事后 Linux 产物验收通过，仍保留原始失败。
3. 第二个模型 `add-cursor-pagination` 第二次超过同样期限。轨迹包含不必要的子代理及模型编造的工作区路径，路径访问被边界拒绝；事后产物仍未通过。没有据单个样本加入针对量化模型的特殊提示词。

细节见两组 `failure-review.json`、逐次 JSONL、`evidence/` 中的事件与候选 diff。原始矩阵的完整提示词/代码指纹和恢复派发记录均保留；补跑仅填未开始的 attempt，不重跑失败空位。

会话并发上限为 4。`pilot.multi.enabled=false` 只关闭 `dispatch_agents`，普通 `spawn_agent` 仍可用；根据请求时间区间，主模型实际请求峰值为 4，第二个模型为 5。第二组有两个会话调用子代理。相关设置在矩阵期间没有变化，见 `plan-addendum.json` 和各组 `event-audit.json`。

## 修复后的追加实验

使用独立冻结构建 `2145dbc`；提示词与原始组相同。定向复测、长链路/后台等待、四种网络故障、预算停止续跑和真正的定时暂停唤醒分别记录，不能与原始矩阵混成一个成功率。具体协议见 [复现说明](reproduction/README.md)。

目前两款模型的 `steer-constraint-hold` 定向复测各 3/3 通过。两款模型的后台等待均 3/3 通过；长链路主模型 2/3、第二个模型 3/3 通过。主模型失败的一次代码测试通过，但模型主动调用 `remember` 创建了约束范围外的 `.pilot/memory-draft.md`。这不是系统自动写入或评测误报，完整工具调用与候选文件已保留在 `corrected/main-scenarios/`，没有放宽允许范围。主模型长链路实际请求数为 9–15，上下文估算从 12,719 增至 20,714–30,431 token；这不是端点精确 token 或费用观测。第二个模型的长链路为 11–12 次请求、约 11.7–22.0 分钟，上下文估算最高 21,691–28,840 token。

首轮预算实验三个初次边界均未保存有效台账；其中两次后来继续完成四十项，一次在自动续跑交接期收到 409，流程失败。`maxSteps=8` 还触发了自动续跑，手动段数不能当作实际运行数。详见 `corrected/budget-review.json`，原结果完整保留。

新构建 `8dc383b` 补预算提醒和续跑开始事件。新的预算组保留原任务与验收，每段请求上限 8、步骤上限 64，最多八个手动段，避免两个上限同时触发；定时唤醒组也在首次派发前改用该构建。具体追加协议见 `plan-addendum.json`。

这次预算组初次边界 **2/3** 保存了有效进度和台账，续跑后 **3/3** 完成全部四十项并通过原始测试。第三次最初仅返回规划文字、没有产物，却被 DIRECT 模式标为完成，仍计初次失败；之后两次继续才完成。没有为这条输出增加针对模型措辞的特殊匹配。三个会话分别用了 2、2、3 个手动段，原有产物未改写，命令均为原始 Node 测试，没有用 shell 循环绕过逐项读写约束。见 `recovery-fix/budget-recovery-review.json`。

首轮真正的定时唤醒为 0/3：两次因任务被强制开源调研且检索失败而停止；一次实际等待、按时唤醒、保留检查点并通过原测试，但模型的最终核验没有给出必需条件的可追溯证据，最终 `NO_PROGRESS`，仍计失败。原样保留在 `recovery-fix/scheduled-wakeup/`。修复默认调研策略后用独立构建 `43dd5be` 追加三次；不删除原失败，也不绕过最终核验。

`43dd5be` 的三次均没有调研调用，均观察到真实等待、按预约时间启动新 run、检查点和只读输入保留、最终原始测试通过，但总体仍为 **0/3**：两次核验无进展，一次达到二十分钟期限后取消。期限快照仍为 RUNNING，取消后的只读数据库证据确认已为 CANCELLED；这两份观察分别保存。详见 `schedule-fix/scheduled-wakeup/index.json`。

这批轨迹暴露了核验请求计数回退；另行回归证明成功等待会因后续写文件而被判为过期。旧模型的原始 `submit_decision` 参数未保存，因此不能断言旧样本每次核验失败都只由等待证据引起。两个确定缺陷分别修复后，用 `bd6a69b` 独立构建追加三次；任务正文、fixture、验收和二十分钟期限不变，核验系统提示词有明确版本变化。

最终三次真实唤醒 **3/3 通过**，各用时约 346、308、396 秒。三次均保留真实检查点和外部确认，按预约时间发起新 run，原始测试通过并正常结束独立核验；请求计数最终为 11、11、14，未再发生回退。第三次核验要求补读当前结果文件，执行器补读后通过，没有修改产物或放松验收。见 `review-fix/scheduled-wakeup/` 与 `review-fix/review-audit.json`。这组三次结果不覆盖此前六次失败，也不足以证明所有模型和任务都可靠。

预算实验区分“至少六项及诚实剩余台账”和“续跑后全部四十项完成”，不能用部分进度测试通过冒充全部完成。调度实验在观察到 `WAITING` 后才提供外部随机确认，并验证不同 runId 按预约时间唤醒，不能用后台命令等待冒充调度恢复。

首轮代理还包含后台能力探测，代理总请求/用量数不能直接当成主会话用量。实验过程中发现的窗口计数污染已用确定性竞态回归修复：在途请求固定开始时的窗口与故障配置，迟到用量仍计入累计预算。正在运行的冻结代理未被替换，原始记录未改。故障覆盖按逐会话失败请求、重试原因和最终验收复核，详见 `fault-proxy-provenance.json`。

四种真实故障组均 **3/3** 通过，共十二次：提前 EOF、空闲停顿、HTTP 503 和连接重置。主会话分别记录 9、9、7、9 次失败及对应重试；停顿在约 120 秒空闲时限结束。未发现重复工具调用身份，也未发现失败模型响应之后、下一条完整响应之前执行工具。连接重置代理记录十次注入而主会话为九次，保留后台探测造成的归因限制，不把代理总数当成会话精确用量。
