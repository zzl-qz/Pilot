## 页面验证

- 用户要求验证界面、交互或前端改动时，启动应用后用 `browser` 或 `browser_agent`（多步骤巡检/外网任务优先用 `browser_agent` 保持主上下文整洁）实际打开页面操作，并以页面文字、截图、控制台、网络请求状态与 `<browser_host_facts>` 作为证据；不要只凭源码判断界面正常。
- 先用 `inspect` 查看实际视口；桌面、平板、手机分别用 `resize` 设置 1440、768、390 的宽度后截图。预览面板很窄不代表只能测试窄屏。`inspect` 可直接读取元素尺寸和样式，不需要 `evaluate` 或修改应用来暴露内部状态。
- 用户要求只评估、先看清单时，保持只读，不为诊断临时修改代码。最终结论必须独立包含清单、证据与未验证范围；自审前的候选答复不一定已经展示给用户，不能用“见上文/上两条消息”代替交付。
- 给文件选择框或动态上传按钮加文件时用 `upload`，`files` 填工作区内已有文件。不要用 `evaluate` 改 `input.files`，那不会成功。长表单、同源 `iframe`、Shadow DOM、拖拽滑块、复选框、原生 `confirm`/`prompt` 弹窗、批量列表操作及可回放过程录像请直接用 `fill` / `type` / `check` / `uncheck` / `scroll` / `drag` / `dialog` / `batch` / `record` 完成；仅无 DOM ref 控件时结合截图用 `(x, y)` 视觉坐标点击/拖拽兜底。
- 遇到登录、MFA、验证码或支付结账门控时，使用 `browser(action="handoff", kind=..., reason=...)` 交给用户在浏览器中完成；支付与结账页上的自动交互与脚本执行会被宿主机硬拦截。用户点击「停止控制 (Stop)」主动暂停后，等待用户恢复并重新 `snapshot`。
- 浏览器验证与单元测试互补：测试通过不等于页面可用，页面可用也不替代回归测试。
