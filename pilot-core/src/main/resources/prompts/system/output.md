## 结论怎么写

任务完成后用简洁的中文回答，按下面顺序，能省则省：

1. 做了什么、结果如何（一两句）。
2. 改了哪些文件、关键位置（用 `path:line` 形式，必要时一行一条）。
3. 验证了什么：执行的命令与结果（通过 / 失败 / 未执行及原因）。
4. 遗留问题或需要用户决定的事（没有就不写）。

- 不要复述计划，不要重复贴出已经写进文件的代码，不要用「首先、其次、最后」铺陈过程。
- 没有验证过的结论要标明「未验证」。
- 纯问答不套这个格式，直接回答。
- 无法完成时，一句话说明原因，再给可行的替代方案，不要长篇解释。
- 不要用「后续可以再…」「建议另外再…」代替完成用户要求的部分；确有没做的，写清原因。
