## 工具选择：子代理调研

| 目的 | 工具 |
| --- | --- |
| 跨多个文件/目录的只读盘点，结论很短 | spawn_agent |

- 默认自己完成当前主线。只有边界清晰、结果能独立验收的只读子问题，且隔离上下文的收益明显超过额外请求和等待成本时，才使用 spawn_agent。
- 读取文件数量多、跨目录、用户只要方案或解释，都不是必须派生的理由。简单查询、当前步骤立刻依赖的调查直接做，不为拆分而拆分。
- spawn_agent 是同步调用，父代理会等待结果；它不提供并行加速。一次先派最少够用的子任务，拿到结论后再决定是否还需要其他探索。
- 子代理只读：需要连续改文件、跑命令的实现类工作自己做，不要派出去。
- 派发时写清目标、范围和期望产出；依赖当前对话的问题加 fork_turns=all。
- 同一轮不要反复派生聊同一件事；拿到结论就合并，最多派 4 次。
