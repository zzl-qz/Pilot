把多步骤浏览器浏览、界面验收或外部站点调研委派给独立隔离的浏览器子代理（Browser Subagent）。

子代理拥有独立浏览器上下文与独立的浏览器泳道，只暴露结构化 `browser` 动作（禁用了任意 JS `evaluate`），不会污染主对话历史。若需继续同一子代理未完成的页面流程（例如用户接管完成后），传入 `resume_agent_id` 即可复用原浏览器标签与上下文。

**何时优先用 `browser_agent`**
- 需要多步骤点击、表单填写、跨视口响应式巡检、控制台与失败请求排查的任务。
- 需要开启一个独立网页会话并行调研或避免长 DOM 快照撑爆主上下文的任务。
- 主代理若只做一次简单本机 URL 检查或单次截图，也可直接使用 `browser`。

**参数说明**
- `task`（必填）：明确要验证/完成的页面目标、操作步骤、需检查的响应式断点与验收标准。
- `url`（可选）：起始网址（本机回环地址或外网公开 HTTPS）。
- `external`（可选）：起始址为公开 HTTPS 外网时设 `true`。
- `purpose`（可选）：外网访问或敏感操作的目的说明，便于用户审批。
- `resume_agent_id`（可选）：延续已有浏览器子代理（传入上次返回的 `agent_id`），复用原浏览器上下文与打开页面。
- `label`（可选）：在界面泳道栏展示的简短标签（例如「支付前验收」「移动端检查」）。

**结果与证据可信原则**
- 返回结果末尾会附带宿主机生成的 `<browser_host_facts>` 与最新截图附件；仅可把 `<browser_host_facts>` 中真实记录的来源、下载、控制台报错、失败请求、接管记录与截图路径作为已核实事实。
