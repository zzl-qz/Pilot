把一件大任务拆成多个边界清晰的子任务，交给子 Agent 并行 / 串行执行。

用法要求：
- 每个子任务只解决一件事，写清目标与验收标准；有先后依赖的用 depends_on 串起来，没有依赖的会并行跑。
- 必须给每个任务划文件白名单 files（glob），并在 goal 里说明可改的范围；越界会被后端拦截而不是「尽量遵守」。
- 只读调研任务 writable=false；需要改代码的任务 writable=true，改动只会进沙箱，用户接受后才落地。
- 风险等级如实标注：核心逻辑、数据库、对外接口用 high。
- 同一问题存在两种合理方案时，reviewers=2 让两个子 Agent 各出一份，结论不一致会自动转人工仲裁。
- 一次 2～6 个任务为宜；子 Agent 之间不通信，拆分时不要假设它们能互相看到对方的产出。

工具会返回结构化报告：任务状态、结论摘要、合并预检、硬校验结果。
出现分歧、变更冲突或校验失败时，报告会明确要求停下来等用户决定——此时不要自行选一个方案继续。
