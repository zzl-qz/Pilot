派一个只读子代理去做一件边界清晰的探索任务：它在独立上下文里翻阅、检索、比对，只把结论交回给你，中间读过的文件不占用你的上下文。

什么时候用：
- 有可独立验收的只读子问题，只需要短结论，隔离大量探索材料能明显节省主线上下文；
- 或用户明确要求委派调查。派发前写清独立目标、范围和产出，选择最少够用的子任务。

这是同步调用，父代理会等待子任务结束，不提供并行加速。读取文件数量、跨目录、只要方案或解释都不是自动派生的条件。

什么时候不要用：
- 接下来还要连续改文件、跑验证——实现类工作自己做，不要派出去；
- 只读一两个已知文件就能回答，直接读更快。
- 当前主线立刻需要结果的短查询，或拆分后只会重复读取同一批材料，自己完成。

用法：
- task 写清目标、范围（哪些目录/文件）和期望产出（要点控制在一屏内）。
- 问题依赖刚才的对话（「那它为什么这么写」）时传 fork_turns=all 把当前记忆带过去；否则默认 none。
- 子代理是只读的：不能改文件、跑命令、再派生子代理。它的耗时和 token 计入本轮预算，同一轮最多派 4 次。
- 4 次是硬上限，不是配额；同一问题不要反复换名字派发，先合并已经获得的证据。
