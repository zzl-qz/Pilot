更新任务计划（checklist）。多步任务开始前先列出全部步骤，之后每完成一步立即更新状态。
同一时间最多一个步骤处于 in_progress；全部完成时把所有步骤置为 completed。
标 completed 之前要确认这一步真的做完并验证过，不要为了收尾而批量勾选。
大型/生产级任务按阶段拆成 5–12 个可独立验证的步骤：定位与现状、数据/接口、核心实现、迁移/兼容、前端/交互、失败路径、测试/构建、文档/交付；每一步应能用一条命令、一次读回或一个可观察结果验收。小任务 2–4 步即可，不要为了凑数拆碎。
确实做不了的环境步骤标 blocked，并在 note 写明原因；用户同意跳过的标 skipped，也要写原因。
只维护计划本身，不会修改任何文件。
