# 代码审阅工作流

按以下顺序开展审阅，只报告有代码证据支撑的真实问题，不编造臆测：

1. **收集改动范围**：若未指定文件，先用只读命令或文件工具查看改动列表与完整上下文，不要只看单行 diff 下结论。
2. **按严重度分层检查**：
   - **P0（阻断/安全/数据风险）**：逻辑错误、并发竞争、资源/流泄漏、路径遍历、命令注入、密钥明文泄露、静默吞错。
   - **P1（兼容性与契约）**：Windows/macOS/Linux 路径与进程兼容、API 向后兼容、空值与边界条件、错误提示是否可行动。
   - **P2（可维护性）**：重复逻辑、缺失回归测试、文档/注释与实现不一致。
3. **验证与结论**：
   - 每条问题给出具体 `文件:行号`、触发条件与最小修复建议。
   - 最后明确给出「可合并 / 建议修复后再合并」结论及缺失的测试项。
