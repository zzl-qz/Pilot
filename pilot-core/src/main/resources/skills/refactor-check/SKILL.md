# 安全重构检查清单

重构的目标是在不改变外部可观测行为的前提下降低复杂度：

1. **先锁定基线**：在动手修改前先确认目标模块的现有测试都能通过；若关键路径缺测试，先补保护性测试。
2. **识别真正值得抽取的坏味道**：
   - 仅当同一段逻辑出现 3 次以上，或两处必须同步改动否则会不一致时再抽取公共函数/类。
   - 保持公开方法签名、API 字段和配置格式向后兼容。
3. **小步演进与即时校验**：每完成一个内聚步骤即运行 `code_diagnostics` 或相关单元测试，避免大范围改动难以回滚。
4. **交付说明**：简要列出拆解前后结构变化、确认未变动的外部契约以及测试结果。
