# Pilot Android 与应用级移动连接

当前版本 `0.2.5-preview`。手机连接的是一台运行 Pilot 的电脑，一次配对即可管理该电脑上的项目与任务。代码和命令仍在电脑上执行；手机不保存模型 API Key。

## 个人自用验收口径

个人自用以“电脑保持运行，手机打开 App 就能管理自己的项目与任务”为验收目标。无需先租服务器、购买商业套餐或完成应用商店上架。APK 已有本机开发签名，可以直接安装；在同一台构建电脑保留签名密钥后继续更新即可。

必需的配对、任务管理、审批、指令控制、草稿、断线恢复、重复提交保护已经实现并做自动化验收。另补充了连接组件异常退出后的自动恢复，以及后台被强制结束后连接子进程自动退出，避免遗留进程影响下次连接。恢复测试使用原手机身份和旧票据，验证授权、任务与提交回执保留。

已在 vivo V2352A / Android 15 上记录到一次蜂窝网络经公网中继读取工作台成功；0.2.2 的连接恢复与性能优化包已完成专用模拟器回归，仍待真机覆盖回归，不能把单次成功当作所有网络均已验收。其他运营商、家庭宽带组合、扫码拒绝权限与长时运行仍待验证。电脑关机或休眠时手机无法执行任务；后台通知暂未启用，回到 App 会同步进度。公共连接服务受限速和可用性影响，这些限制对个人自用同样成立。

自用时可沿用源码项目的现有后台。若改用便携包连接现有数据，应设置 `PILOT_DATA_DIR` 指向原数据目录；默认在包目录新建 `.pilot`，不会自动搬走原来的项目或历史。更新便携包时保留原数据目录和 APK 签名密钥。

## 当前工作流

移动界面使用自定义 Compose 设计系统：中性色面板、清晰的任务状态、紧凑输入区和四个固定导航入口。设备页可以选择深色、浅色或跟随系统，偏好保存在本机；返回任务列表时保留搜索、筛选与阅读位置。触控操作按 48dp 设计，窄屏与系统大字体下可以滚动、换行。

- **电脑连接入口**：Web / 桌面最左侧导航栏 → 连接手机。直接在工作台弹窗中生成二维码，显示有效期、配对成功、在线设备与撤销授权。成功后显示设备名称和“完成 / 添加另一台设备 / 查看已配对设备”，收起已经失效的二维码和复制操作；“完成”只关闭弹窗，手机继续连接。再次打开时，已有授权且没有进行中的配对会优先显示设备列表。桌面优先使用受限的原生剪贴板写入；浏览器自动复制失败时显示可全选的完整配对码。
- **任务**：跨项目查看、搜索、状态筛选、置顶、重命名、归档 / 恢复、新建。项目已有空白任务时，可以打开现有任务或明确选择归档后新建。
- **项目**：查看已有项目、从电脑目录浏览器新建项目、重命名、在项目内发起任务。
- **收件箱**：集中查看所有任务的待审批和结果。审批带任务与运行归属；归属尚未同步时不能盲目批准。审批被电脑处理后，手机刷新移除，不重复执行。
- **任务详情**：实时事件、历史分页、收起执行过程、输入 / 排队 / 引导、队列编辑 / 删除 / 上移、暂停 / 继续 / 停止。“资料”菜单集中提供成果、改动和用量，详情以可收起的底部面板打开；工作区差异明确包含其他任务可能产生的改动。
- **原生输入**：系统文件选择器上传附件、系统语音识别将文字填入草稿。无文件选择器 / 无语音识别服务会明确提示替代操作，不假装成功。
- **设备**：保存多台电脑并切换。设备身份与草稿用 Android Keystore 加密；每台电脑的数据隔离。忘记某台电脑只清理其手机侧记录，电脑任务继续运行。

一台电脑最多授权 16 台手机，可同时连接；每台新手机需用单次配对码分别授权，撤销一台不影响其他设备。手机一次连接一台电脑，保留最多 16 台电脑记录。置顶属于本手机偏好；项目、任务、队列、审批和结果状态由电脑统一保存。

## 连接与恢复

后端 `MobileConnectionService` 统一管理连接桥的生命周期。Web 和桌面共用 `<pilot.data.dir>/mobile` 中的电脑密钥与设备授权；关闭配对弹窗不关闭连接。首次启用后，后端重启会自动启动连接桥；连接桥异常退出也会自动恢复，失败时逐步退避至每分钟重试。后台正常或强制退出后，连接桥随之结束。Java 子进程使用与后端一致的运行时和解析后的访问令牌；令牌不下发手机。

传输采用 iroh 的加密 QUIC（FFI 统一锁定 1.1.0，规避已复现的 1.2.0 原生 DNS / TUN 兼容问题）：默认自动使用公共发现与中继，尽力直连，必要时回退中继；后端可显式选择仅直连，或指定自己的中继。二维码固定电脑公钥。配对码 5 分钟、一次有效，重新生成立即使旧码失效。管理入口只接受本机同源请求，手机路由白名单不开放设置、配对管理或任意代理。

协议升级为 `pilot/remote/2`，手机和连接组件需一起更新。旧 0.1 预览版的独立桌面桥使用过另一份身份目录，升级后需要重新扫码一次；任务和项目数据不迁移也不删除。新的协议版本避免旧桥忽略请求标识后静默重复执行。

修改操作带设备绑定的唯一标识，后端先写占位回执再执行，已完成的相同请求重放原响应。进程异常导致结果未知时拒绝自动重做。手机把未确认请求加密保存，显示“核对提交结果”；不会在网络恢复后无条件重发命令。该机制不宣称任意硬件故障下的分布式 exactly-once。

手机回到前台会重连，读取应用快照并按事件游标续接。历史可向前翻页，查看旧记录时暂停追随新消息；提供“返回最新记录”。事件和正文窗口有字符 / 条数上限，单条超长正文会明确标注截断。

移动快照只包含列表需要的结果摘要，完整结果按需读取。未变化时返回版本确认，避免每 5 秒重传全量；任务首屏读取最近 60 条事件，向前每页 100 条，历史、运行状态与队列并行请求。JSON 响应采用协商的逐帧 gzip，SSE 与二进制文件保持原样；旧 `remote/2` 手机不声明压缩能力则仍收明文帧，新手机遇到旧后台或连接桥会退回全量 / 明文。要获得全部优化，需要更新电脑后台、连接桥和 APK；保留配对与任务数据，无须因本次更新重新配对。首次同步与手动刷新有进度反馈，同步中不会反复取消同一快照读取。

## 安装与开发

普通 PC 源码运行直接使用仓库 `start.sh` / `start.cmd`，只准备电脑端的 Java 25、Node、Maven 与 Electron。不会因此下载 Gradle、Android SDK 或 Java 21，也不会自动构建 APK / 连接桥。手机功能需要开发者先按下列命令另外打包；打开手机连接窗口才验证已打包的桥及电脑原生运行库。说明见 [源码环境自动准备](../SOURCE_ENVIRONMENT.md)。

普通预览包包含 Android APK、后台 Jar、连接桥和当前系统的 Java 运行时。启动 `start.sh` 或 `start.cmd`，浏览器打开 `http://localhost:9999`；Pilot 桌面也可连接这个后台。手机安装 APK 后扫描电脑的配对码。电脑需保持在线且不休眠。

源码开发：后端使用 Java 25，Android / Gradle 构建使用 Java 21 与 Android SDK。设置 `JAVA_HOME`、`ANDROID_HOME` 后执行：

```text
node scripts/mobile.mjs build
node scripts/mobile.mjs test
node scripts/mobile.mjs qa
node pilot-mobile/scripts/android-smoke.mjs emulator-5580
```

只需要在电脑生成配对二维码、已有手机 APK 时，安装 Java 21 后可单独执行 `node scripts/mobile.mjs build-bridge`。它只构建电脑连接组件，不需要 Android SDK；后台仍使用 Java 25。仅运行 Maven 不会生成 `pilot-mobile/bridge/build/install/bridge/lib`。更新源码后重新构建连接组件及后台，并重启原后台进程，旧 Jar 不会因拉取代码而自动更新。

Windows x64 使用上游包内的 `win32-x86-64/iroh_ffi.dll`，并非仅支持 Mac。该 DLL 导入 `VCRUNTIME140.dll`；若界面明确提示“Windows x64 原生连接库加载失败”，请检查或修复 [Microsoft Visual C++ x64 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)，同时检查临时目录可写以及安全软件是否拦截原生库。运行库缺失只是可能原因，不能凭通用 Service Error 判定。不要从不明网站单独下载 DLL，也无需关闭全部防火墙或安全软件。

旧代码曾使用 `Path.resolve("*")` 拼接 Java classpath，在 Windows 会触发非法路径；提交 `c2ee9a6` 已改为字符串拼接。Windows 源码启动遇到二维码不出现时，应先确认后台包含该修复。连接管理接口现在显式返回故障说明，不依赖 Spring 是否公开异常 message；子进程只提取已知故障类别，原始输出与管理凭证不会显示到页面。

构建后端沿用仓库 Maven 流程。打包便携后台时 `JAVA_HOME` 指向 Java 25：

```text
node scripts/package-mobile-host.mjs <新的输出目录>
```

打包器原子生成新目录，拒绝覆盖已有包；包含 Java 运行时的许可文件。当前生成的是后台便携包，桌面壳的正式安装器与签名仍使用独立发布流程。

发布签名：设置 `PILOT_ANDROID_KEYSTORE`、`PILOT_ANDROID_STORE_PASSWORD`、`PILOT_ANDROID_KEY_ALIAS`、`PILOT_ANDROID_KEY_PASSWORD` 后运行 `node scripts/mobile.mjs release`。缺少配置会直接失败，避免把未签名包误当正式发行包。普通 `build` 只生成开发签名的预览 APK；正式密钥不进入 Git。

可用 `pilot.mobile.libraries` 指定连接桥 `lib` 目录；默认识别源码构建目录和便携包目录。`pilot.mobile.mode` / `PILOT_MOBILE_MODE` 默认为 `auto`，未指定中继时启用公共服务；设为 `direct` 则禁用公共发现和中继。`pilot.mobile.relay` / `PILOT_MOBILE_RELAY` 非空时只用指定中继，手机用户无需填写。独立诊断入口仍为 `node scripts/mobile.mjs bridge`，其数据目录需显式指定，不能把它与应用后台同时当作同一电脑身份运行。

## 平台与当前限制

| 平台 | 处理方式与验证范围 |
| --- | --- |
| Web | 后台托管连接桥；本机同源管理；浏览器剪贴板能力检测及手动复制。Chrome 三种宽度已验收。 |
| macOS | Apple Silicon 本机 Java / Electron / 原生剪贴板 / QUIC 已验收。Intel macOS 缺少上游 iroh 原生制品，明确拒绝启动连接桥。 |
| Windows | x64 原生库、Java 参数数组、标准路径和 `java.exe` 分支；模拟测试和 CI 配置，未做 Windows 实机。ARM64 缺少上游原生制品。 |
| Linux | x64 / ARM64 原生库；Linux 容器与 macOS 公网中继往返已验证，未做 Linux 桌面实机。 |
| Android | minSdk 26，targetSdk 35，四种 ABI，Keystore、关闭备份。专用模拟器验收通过；vivo / Android 15 单次跨网读取已记录，最终修复包真机回归待完成。相机权限边界、全部 Android 版本和 OEM 尚未全面覆盖。 |

- 单附件不超过 2 MB，单次总量 6 MB、最多 16 个；手机成果下载上限 16 MB。
- 正文支持可选择的段落、标题、加粗、行内代码和可横向滚动、复制的代码块；未结束的流式代码块继续展示。复杂 Markdown 表格与内嵌 HTML 保留文本显示，复杂文件可保存到手机后由对应应用打开。iOS 不在此 APK 交付范围。
- **尚未上线后台系统推送**。App 退后台可能被系统暂停；重新打开同步状态。界面与 capabilities 明确标为不支持，不能把常驻 SSE 当作锁屏推送。
- 默认启用公共服务，尽力直连，必要时中继；不保证所有运营商、代理或防火墙下都可用。两个独立私网的纯直连仍取决于 NAT 和防火墙。共享付费中继的认证适配未实现。
- 正式 APK / 桌面安装包签名、分发、更新回滚和全平台真机属于发布验收，不能用本机成功替代。

## 扫码与电脑身份

手机扫码使用 Pilot 自有竖屏页，可直接返回或切换到粘贴配对码。相机拒权时提供授权 / 设置入口；无相机或相机暂不可用时仍能手动连接。扫到其他产品的二维码会留在扫码页提示，不会提交连接请求。

同一个 APK 使用相同协议扫描任意受支持电脑生成的配对码，不依赖某台开发用 Mac 的地址。每张二维码包含生成电脑的动态连接票据和五分钟单次凭证，因此只授权连接那台电脑；其他电脑必须生成自己的码。二维码不是跨电脑共用的万能口令。手机可以保存多台电脑并切换，电脑可以分别授权多台手机。

设备身份运行时保存在 `.pilot/mobile`（或显式数据目录），不会随 Git 源码发布。分发源码或便携包时不要把某台电脑的 `.pilot/mobile` 运行数据复制给其他电脑，否则会把身份和已有授权一起复制。

专用模拟器验收：先执行 `node scripts/mobile.mjs qa`，然后运行 `ANDROID_HOME=... node pilot-mobile/scripts/scanner-smoke.mjs emulator-xxxx`。该脚本只接受名为 Pilot 的模拟器，重置独立 `.qa` 包，不操作真机。Windows 请用对应 PowerShell 环境变量语法。

## 0.2.5 的跨网连接与本地出码

经用户确认，默认恢复自动公共连接服务。二维码在本机生成，不等待手机、DNS、发现或中继上线；跨网准备在后台超时重试。状态接口和窗口单独显示准备中 / 暂不可用 / 已完成初始化，不将二维码渲染成功视为跨网成功。网络地址就绪后，轮询自动刷新二维码路由，保留同一凭证和原有效期；不会复活已使用或过期的码。初始化状态不是持续在线保证，实际直连或中继路径以手机显示为准。

后端 application-local.yaml（保留原有配置）：

```yaml
pilot:
  mobile:
    mode: auto # 默认公共发现与中继；只要纯直连则改为 direct
    relay: "" # auto 时可指定真实的 https://relay.example.com:443
```

`direct` 与非空 `relay` 互斥。指定中继不会回退公共中继；即使指定服务不可达，本地仍可快速生成二维码并显示网络准备失败。中继必须是真正的 iroh HTTPS 服务，不能填写 HTTP 代理或 STUN 地址；证书仍正常校验。源码 PC 启动无需因此检查或下载 Gradle / Android SDK，移动构建继续单独进行。

手机和电脑连接桥一起更新至 0.2.5-preview 后，重新生成并扫码一次，更新 0.2.4 保存的仅直连信息；电脑身份、任务和项目保留。旧的显式直连记录不会被手机静默改为公共模式。

FFI 1.2.0 在本次 TUN / Fake-IP 环境中持续 DNS 失败；相同设置下官方 1.1.0 完成握手及实际公网数据往返，因此电脑和 Android 从同一 Gradle 属性锁定 1.1.0。未修改系统代理、DNS、hosts 或证书。其他代理组合仍需各自验证，网络未就绪时给出 TUN / DNS 提示。

验收命令（桥已构建，容器镜像已缓存）：

- `node pilot-mobile/scripts/direct-qr-smoke.mjs --container`：自动模式的实际 PNG 出码及完全断网行为。
- 同一命令加 `--direct`：显式直连模式。
- `node pilot-mobile/scripts/relay-smoke.mjs https://aps1-1.relay.n0.iroh.link./`：两端只绑定回环且去除票据直连地址，强制验证公共中继实际往返。仅传固定探针文本，不读取用户项目。
