它到底改了什么

每次调用、每个文件、每条验证都落成事件，最终汇成 diff 与检查清单。

事件 → 存储 → 重放，同一份数据喂给界面和审计

自动执行有多危险

三处不好写的地方

这里的取舍比功能列表更能说明项目现在处在什么水平。代码摘自当前仓库，不是示意。

ContextBudget.java java :54 
boolean apply(List<Message> messages, int limit, Consumer<SessionEvent> events) {
    int charBudget = Math.max(1, limit);
    int tokenBudget = charBudget;
    double usage = usage(messages, charBudget, tokenBudget);

    // 第一、二层不花模型调用
    if (usage >= PRUNE_RATIO) {        // 55%
        ContextCompactor.pruneToolOutputs(messages, limit);
    }
    if (usage >= TRUNCATE_RATIO) {     // 70%
        ContextCompactor.truncateLongToolOutputs(messages);
    }

为什么两个预算同值。英文 4 字符约 1 token，中文接近 1 字符 1 token。只按字符判断，中文会话会在真正接近窗口前被当成「还很空」。

为什么先做不要钱的。占位符化和截断只是 O(n) 遍历；摘要要花一次模型调用，还必须接受细节永久丢失。

只做 startsWith 会被绕过。工作区里一个 link → /etc 的符号链接，link/passwd 前缀检查是通的。

为什么要「现存祖先」。新建文件时目标还不存在，直接 toRealPath() 会抛异常；取现存祖先再拼后缀，两种情况都覆盖。

超时默认拒绝。completeOnTimeout(false, …) 把安全侧写进类型系统：没人处理也不会变成放行。

阻塞但不轮询。线程停在 Future 上，用户点击即唤醒；轮询写法会把延迟和 CPU 一起搭进去。

安全

四档权限，按可逆性分级

不是按「危险程度」一刀切：文件改动有快照可回滚，命令的副作用没有等价物。

档位读工具写文件执行命令适用场景
READ_ONLY默认 放行拒绝拒绝 先看看它想干什么
ASK 放行逐次审批逐次审批 认真改代码，但每步想确认
AUTO_EDIT 放行直接执行逐次审批 信任编辑，仍需看住命令
AUTO 放行直接执行直接执行 仅限可丢弃的隔离工作区

权限不是操作系统沙箱。路径限制与命令白名单不能替代容器或独立账户隔离，使用真实模型时请先备份并优先在可丢弃工作区试用。

已知边界

它现在还做不到什么

如实记录，比含糊其辞更有用。

不是沙箱

命令内部的越界、子进程网络访问、提示注入越权，只能靠容器与可丢弃工作区解决。

token 是估算值

中文按 1 字符 1 token、英文按 4 字符 1 token，可能比真实 tokenizer 更早触发压缩。

摘要不可逆

被折叠的对话细节只剩摘要，续跑时可能需要复读原文件。

命令副作用不可回退

检查点只覆盖写工具记录的路径，sed -i 或构建产物不在恢复范围。

多智能体不自动合并

冲突与结论分歧一律交人裁决，这是刻意的产品选择。

没有成本统计

响应里的 usage 被丢弃，token 花费无法对账；上下文预算按字符估算。
